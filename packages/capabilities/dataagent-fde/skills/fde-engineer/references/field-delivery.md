# 现场探查、工程交付与运维

## 前期 · 从一个实例确认现场

1. 请经办人指出一件实际输入和理想结果。跟随它走过采集、人工判断、系统处理和使用结果的人，找出在哪一步耗时、漏项或出错。已有演示、历史运行、指标定义和输出样例可直接用；只补影响决策的信息。
2. 分别观察每个来源的一条记录代表什么、标识和时间单位、取值与缺失、更新周期和版本。关联两份数据前比较键的唯一性和关联前后数量；对文档、事件或设备信号使用相应的页段、事件号或采样时间定位。区分样本可证的事实和仍待验证的总体情况。
3. 查现场已有的接口说明、项目清单、测试入口、配置项名称、运行环境和调度方式；在已授权位置做最小只读验证。交代哪些输入可达、哪里可以试跑、哪些系统仍需负责人接入。
4. 用可核对的结果请业务方做具体选择。例如同一个“门店转化率”可以表示成交笔数或成交人数除以客流，只有其中一种能用当前数据计算。记录选定的粒度、判定条件和一个期望输出。单次查证可直接交付结果。

## 中期 · 打通和验收工程链路

1. 从现场真实入口复现当前行为。确定输入结构、转换规则、输出位置和调用者。在已有作业、接口或项目中选最短路径，用一例从源到目标运行，再处理已知变体。交付实际代码、配置或可执行作业，并说明从哪里启动。
2. 对每个会改变结论的加工步骤保留一个检查，例如解析后的单位、联接后的行数、分组前后的合计、目标记录的业务键。用独立的预期值核对正常、边界和错误样本。保留一条现场可重跑的验证命令。重复导入、断点续跑或并发重试属于任务范围时，隔离模拟中断，并把同一批输入执行两次，比较两次的目标状态。
3. 交代输入版本、依赖、参数、实际输出、异常分支、恢复位置和验收差异。部署在委托范围内时，使用原有发布入口和批准机制，先验证小范围运行，回读目标结果。只在测试环境运行过，就按测试环境交付。

## 后期 · 从异常信号到恢复

1. 建立运行基线。选能体现业务结果的信号，例如产出是否准时、覆盖量、重复率或工单积压。沿用现场已有阈值、时窗、告警去向和责任人；缺少基线时先取一次可重复观察并标出待确认项。接入持续运行时验证调度确实触发、告警可以到达约定位置。
2. 对告警定位最后成功运行、首次失败、变更版本、受影响的键或时间窗口，用日志和目标端回读区分输入缺失、加工失败、部分写入以及结果尚不可见。把未验证的解释作为假设，选择能区分它们的检查。
3. 写入结果不明时，按业务键或回执查目标状态。先在副本重放，确定补跑范围、幂等性、停止或回退条件。现场已授权时执行相应处置，再从目标端对账，并在约定观察窗口重新检查原告警指标。只有日志或样本权限时，给出已验证范围、仍需哪项读取或操作权限，以及接手人的具体下一步。
4. 交接时留下当前版本、运行入口、观察指标、常见故障的第一项检查、修复或回退方法、未决影响和负责人。发生过的错误可变成回归用例；业务口径变化要重新确认受影响的验收样例。

## 可选的本地小样检查

已有查询、测试和目标端读数优先。拿到 UTF-8 CSV 小样且宿主能运行 Python 3 时，以下命令可从本 Skill 目录运行。路径换成现场已获准读取的样本。

```sh
python3 scripts/sample_check.py profile sample.csv --key site --key day
python3 scripts/sample_check.py compare expected.csv actual.csv --key site --key day
```

`profile` 返回行数、逐列空值数、候选键缺失数和重复行数；用它检查粒度假设。`compare` 按单键或复合键对齐两份小样，忽略行列顺序，保留标识前导零等原始文本。它可用于验收预期与实际输出，也可比较两次隔离运行后分别取得的目标快照。退出码 0 表示检查完成（对比时表示一致），1 表示差异或证据不足，2 表示输入无法读取或解释。两个空样本也属证据不足。只有从实际目标取得的快照才能说明该目标的状态。
