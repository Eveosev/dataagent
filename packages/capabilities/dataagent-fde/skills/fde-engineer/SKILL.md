# 从用户手头的一件事开始

**制度提取的第一次读取。** 用户给目录或含多份原件的附件时，先只列文件名。若只需一份原件、几个候选都可能符合且用户尚未选定，此轮就列出候选、询问选择并等待。即使只想看标题，也不要预览候选正文，或把正文读取与读本指引、列目录放在同一批调用里。已明确指定的原件可直接读，包括用户明确要求比较的多个版本。

就在用户当前的对话里工作。用户说“提取”，就交付提取结果；说“以后也这样办”，才转入教学。普通附件或宿主已有权限读取的文件就可以开工。按当前可用能力选择工具，读懂一个文件无需启动工作台、连接 MCP 服务或建立事项库。

收到“帮我提取下 xx 文件的制度”、对版本问题的回答，或对已提取条款的纠正时，使用[制度提取与引文核对](references/policy-extraction.md)。同一对话保留委托、候选文件、范围和历史表头。多版本时先问用户，答复接回上次停下的位置。该流程随附一个可直接运行的本地文本核验工具。

## 首轮怎样决定做什么

1. 从本轮请求、附件和已给的路径辨清对象与交付物。先看用户给的示范，以及当前现场已授权、与本件直接相关的历史轨迹，例如上次的结果、操作记录、文字指引或录屏。沿用仍适用的步骤、字段或输出习惯；业务结论回到本次有效原文核验。限定在当前可读范围内，没有可用轨迹也能办首单。
2. 文件唯一、目的清楚时直接办。若有多个同名版本、指代不明或两种合理范围会改变交付，先把必要的问题一起问清，例如“目录里有现行稿和征求意见稿。这次用哪份？要提整份，还是只看差旅报销？”仅在两项都不清楚时才都问。文件未提供且找不到时，邀请用户附上文件、给可读路径或粘贴相关原文。
3. 按回答探查已获准的材料。读到影响结论的版本冲突、缺页、例外或口径分歧时，交付可核实部分，指出仍缺哪份材料或需要谁决定。对象和范围清楚时，输出格式可先采用易核对的默认值。

## 经办人应当收到什么

- **提取制度。** 根据实际原文归纳规则、适用条件及例外，每项附文件名和条号、页段或表格位置。保留“且／或”“事前／事后”等会改变执行的限定词。原文缺少的金额、材料或例外标为未说明。需要说明旧做法与现行制度有差异时，指出哪条改变、以哪处原文为据。只委托提取时，到交付制度为止。
- **查原因或办一件事。** 先给已查明的结果及依据。若解释不唯一，说明什么证据可以区分它们。给用户的是值得确认的范围、会改变决定的发现、最终结果或确实阻塞的问题。文件探查、识别、索引和内部记录由宿主在后台处理。
- **教会以后做。** 用户明确要求复用时，从已确认步骤整理适用范围、例外、接手人及一个能区分分支的样例。只把获准保存的内容写到指定位置。用新例验证后说明哪些情形已验证，业务启用由有权人确认。一次特批只随本件。

沿用当前宿主的身份和工具权限。缺少可选工具时，先看获准的原生读取能否解决；只能读部分材料时说明覆盖范围。需要扩读其他来源、用客户材料接新工具或在外部系统写入时，说明目的与影响并按宿主机制取得相应许可。外部操作的结果用目标系统回读；未确认时标为待查。
