# 在现场交付和维护一项业务能力

在用户惯用的 coding agent 中接手委托。先确定谁会使用结果、现在要解决什么、用什么实际观察能判断办成。沿用现场的业务用语。已有系统出故障可直接从运维开始；只要一次提取、分析或诊断时，做到该次交付即可。需要从零落地时，贯通探查、工程交付和运行维护。

## 接手与续办

- 从用户指定的附件、目录、系统和已有做法入手。在当前授权范围内先做能区分情况的最小探查。目标需要多个来源时分别取样；若只需一个原件且版本未定，先只列候选名称，等用户选定再读正文。
- 用当前样例、反例或历史结果和业务人员对齐。历史可提供表头、步骤和习惯，当前规则以有效原件或责任人的确认为据。两个解释会改变产物时，把实际差异和必须确认的问题一起交给用户。答复后沿用原目标、材料和已确定项，从受影响步骤继续。
- 只向用户呈现会改变决定的发现、必要问题、可核验的阶段成果和仍阻塞的事项。后台保留够用的来源、版本、判据与失败位置。同一对话可直接续办；要跨人或跨日交接时，在授权位置留下完成项、待决项和恢复入口。

## 按委托进入相应环节

| 环节 | Agent 执行的工作 | 给现场的产物 |
|---|---|---|
| 前期 · 数据、环境和业务探查 | 跟一件真实样例走现行流程，辨认使用者、源和去向。检查代表性数据的口径、质量和例外，查可用接口、运行位置、权限和已有工程入口。对会影响结果的分歧，用样例请能决定的人确认。 | 可核对的现状、已确认的目标与验收样例，以及仍影响交付的缺口。 |
| 中期 · 工程实现与验收 | 复用现场已有组件，从一个样例打通输入、加工到输出。在用户委托范围内实际修改和运行链路，再测正常件、边界件和失败重试，把结果与约定样例核对。 | 可运行的实现、复现入口和验收结果。交代运行依赖、已验证范围和剩余问题。 |
| 后期 · 运行、恢复与改进 | 从业务信号、最近成功运行和受影响范围定位问题。核对目标系统实际状态，验证修复或回退，沿原指标观察恢复；把有效检查和恢复办法交给日常经办人。 | 当前运行状态及依据、已执行的处置、待办和接手方式。需持续运行时交付现场可管理的调度、监测与恢复入口。 |

## 怎样使用宿主的 harness

Harness 指宿主提供的工具和执行机制。先找现场已有的取样、构建、测试、调度、日志及目标回读入口；能用就调用。运行前核对环境、输入版本和可执行范围。每次检查留下期望、实际观察和下一步；失败时从首先出现偏差的位置缩小范围。外部写入结果不明时先按业务键回读，再决定能否重试。生产发布、回退和外部写入遵循现场已有授权。持续监控须有实际运行的服务和接手人。

- 接手现场、串工程或排故时，按当前环节使用[现场探查、工程交付与运维](references/field-delivery.md)。宿主没有专用工具时，可用原生只读查询、文件、命令和测试完成等价检查。
- 委托涉及制度、规范或作业指引的条款提取时，使用[条款与原文核对](references/policy-extraction.md)。其他业务按各自材料和验收样例选择方法。
- 用户明确要复用做法时，保留适用范围、例外、接手人和一个能区分分支的新样例。将获准保留的内容写到指定位置，说明已验证的情形。
