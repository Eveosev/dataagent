# 跨层契约与组合约定 v0.1

本文用于对齐四组设计草案。模块可以互相调用能力，但共享对象的含义应保持一致，源码依赖和正式生效权限也必须明确。它补充各层的接口表，不额外增加原子能力编号。

## 1. 交接对象与主要责任

| 对象或事件 | 主要产生/维护 | 主要消费 | 交接要求 |
| --- | --- | --- | --- |
| `ResourceRef / SchemaRef / TableRef / DocumentRef` | DA01/02，DA13 可产生物化表 | DA03/05/06/07/08/11 | 真实源版本、原文位置和完整性不能在跨层时丢失 |
| `SemanticDraft / SemanticRef / MappingRef` | DA03 | DA05/06/08/11/12/15 | 草案、已保存、正式生效与废弃状态分开；定义版本和业务时间分别表达 |
| `TaskContextRef` | DA04.5 | 各模块、DA17.3 | 本次任务绑定与假设有修订号；业务环境默认值不是任务已实际选用值 |
| 召回候选集合 | DA05 | DA06/08/18 或 Agent | 保留候选身份、作用域、实际版本、相关性来源和检索覆盖，分数不等于业务正确性 |
| 逻辑/可执行计划与程序引用 | DA06、DA08.6 | DA07/11/14 | 包含输入绑定、目标后端、依赖、实际表达/程序引用与未决条件；生成不表示已执行 |
| 执行结果与回执 | DA07 | DA04/08/10/11/12/14 | 实际调用、状态、结果引用、分页/采样范围及副作用状态可追溯；未知不改写为失败或成功 |
| 分析/预测/优化结果 | DA08/09 | DA10/11/18 | 标明方法、口径版本、数据范围、假设与不确定性；建议不自动产生执行权限 |
| `ValidationReportRef` | DA11 | DA04/06/12/17/18 | 明确正式判据、样本角色、实际依赖、检查范围、覆盖缺口和成本；调用成功不等于验收通过 |
| 策略决定与获准变更 | DA12；涉及委托审批由 DA16 协作 | 存储、检索、执行、导出及发布路径 | 绑定主体、动作、目标、版本、条件和有效期；不得复用过期或目标不匹配的批准 |
| 动作契约版本 | DA15，含义来自 DA03.11 | DA05.8/06/07/16/18 | 具体工具绑定和参数契约可解析；声明支持预演/补偿不代表已经实际完成 |
| 作业、等待与恢复记录 | DA07.9 维护作业；DA14.6 维护等待恢复 | Agent、交互层及任务上下文 | 用作业号、任务修订和事件 ID 关联；恢复时读取实际作业状态，不能盲目重放副作用 |
| 业务环境配置 | DA17 | DA04.5/06/07/18 | 环境标识与租户分开；默认版本可更新，任务仍引用已选修订 |
| `ArtifactRef / MemoryRef` | DA04 保存内容/版本及来源 | DA05/06/08/12/18 | 内容、适用条件、依赖和验证均可定位；共享范围与可信状态分开 |
| Skill/Preset/Bundle 组合 | DA18，内容复用 DA04，策略复用 DA12 | Agent、GUI/TUI 或持续任务 | 描述业务目标、输出要求、能力依赖与可替换点；正式包格式待平台适配，不将示例描述冒充兼容产物 |

对象可在各层有更细的特化类型，例如具体预测结果或策略决定；基础引用类型保持同义。对一个字段或关系需要同名但不同含义时，应先给出区别和映射，而不能凭同名直接转换。

## 2. 六组必须对齐的边界

### 2.1 检索、存储与验证

DA05 从已授权来源中返回候选对象，可按需调用数据读取或索引端口；DA04 保存执行记录和资产；DA11 判断候选计划、方法和结果是否满足要求。DA05 可以返回文档锚点和检索依据，不因此承担证据链持久化；审计由 DA12 使用真实轨迹和结果引用建立。检索不到数据、数据不存在、当前无权读取应分别表达。

### 2.2 语义定义、代码生成与执行

DA03 定义业务含义及适用范围；DA06 绑定定义并生成 SQL、API 调用、表达式或计算依赖；DA08.6 生成/修复通用程序；DA07 运行实际计划和程序。生成函数可以产出可执行内容，但不能用“生成成功”代替运行回执，也不能替正式语义改口径以消除报错。

只有 API 时，源端不支持的聚合由取数后的函数或代码实现；数据页数、过滤范围和源一致性必须传入结果验证。完整分页读取也不自动保证跨页同一快照，需要保留源端限制。语义不支持 SQL 不构成另建一套虚构 SQL 接口的理由。

### 2.3 访问策略、委托审批与执行控制

DA12.1 管数据/记忆/检索/导出的访问及脱敏要求；DA16 管代理身份、委托、审批与人工介入；DA15 声明动作的具体契约；DA07.7 在运行时落实控制并路由到具体执行适配器。已有平台或源端授权可通过端口复用。

证据达标只满足业务依据要求；是否有权执行仍须满足授权策略。若已有明确授权、策略允许且必要验证满足，可以直接生效，无须再统一追加一次人工确认。可见范围、脱敏策略和正式业务标准不得因 Agent 换方法而放宽。

### 2.4 版本持久化、发布与任务绑定

各数据模块保存实体内容并返回实际 revision；DA12 定义其版本状态、生效及回滚策略；DA04.5 固定本次任务实际使用的版本；DA17.2 管业务环境默认版本；DA12.6 检查这些内容和程序能否真实重现。包版本、代码 revision、数据快照和业务生效时间不能互相替代。

批准变更与实际写入有时间间隔时，写入前仍检查当前版本及授权条件。外部系统与资产库无法原子提交时保留逐项回执和中间状态；资产回滚不等于业务副作用已撤销，副作用由 DA07.8 对账或补偿。

### 2.5 实际调用、长作业与流程恢复

DA07.9 提交作业、查询状态和读取部分/最终结果；DA14.6 等候回执、人员或外部条件并恢复流程；DA04 记录真实事件和关联任务修订。等待超时应保留已发出的请求身份，未知副作用先查询而非重新提交。事件可能重复或乱序，应通过事件 ID、作业 ID 和版本条件处理，不能假定通知只来一次。

DA14 的任务重新触发或 DA17 的实例回退也不自动获得重复执行已完成动作的权限。重跑、补算、回滚代码、补偿业务动作分别表达。

### 2.6 方法改进、经验沉淀与业务验收

Agent 可以通过 DA06 重规划、DA08.6 修程序、DA18 改 Skill 或组件组合；DA04 保存有效轨迹和候选经验；DA11 在约定范围上验证；DA12 决定对应资产何时和在哪个范围生效。

端到端结果可与令才等参考业务的效果比较；不要求规则提取数量、内部表达式树或调用顺序完全相同。若业务另行要求兼容某种表达式引擎，则对该部分追加语义一致性验证。开发样本与未见验收样本分开；质量、覆盖、UNKNOWN、人工量、成本与时延同步看，不能只通过缩小覆盖改善分数。

## 3. 拟议代码依赖

各层文档保留自己的 Python 命名空间与目录：`dataagent_data`、`dataagent_application`、`dataagent_governance`、`dataagent_operations`。这些是拟议边界，不要求四个独立服务，也不保证目录名就是最终发行包名。

基础契约目前定义在数据层设计中；进入实现时可将其独立构建为共享 contracts 包，也可以初期保留定义位置并只发布轻量契约产物。无论哪种方式，都保持一个类型定义来源，避免应用层与治理层各自复制 `TaskContextRef`、`CapabilityResult` 或基础引用。

源码原则：能力实现依赖共享契约与端口；后端适配器实现端口；装配入口绑定具体组件。跨层调用不要求直接导入另一层内部实现。

```text
                     共享类型 / 能力描述
                         ↑  ↑  ↑  ↑
             数据能力  应用能力  评测治理  运行交付
                 ↓         ↓        ↓        ↓
                    各自声明的调用端口
                             ↑
                   适配器与任务装配入口
```

例如应用层执行时通过 PolicyPort 消费授权决定，通过 TracePort 记录真实事件；治理层评测可以通过 ExecutionPort 调用已获准且隔离的执行实现，而不导入应用层运行包的内部类。若计划、报告等特有契约出现双向消费，提取其契约类型到轻量共享产物；不为避免循环而复制两种含义相近的结构。

模块内部可以组合其他原子能力；代码依赖必须无循环。共享存储后端不表示职责合并：关系存储可共用，但数据处理边、业务定义依赖、实体关联及实际产物来源保持不同边类型。

## 4. 一个动态组合过程

1. 用户从“客户 A 上季度最大订单是多少”开始；DA05 从值召回客户及相关数据/语义候选，DA03 解析适用业务口径与时间定义。
2. DA06 发现源端只有 API，计划分页取数后用函数或程序计算；DA01 的读取适配器返回分页与快照条件，DA07 返回实际执行及中间结果引用。
3. DA11 发现分页未完或跨页数据变化；返回已检查范围和缺口，Agent 补读、选择源端导出或明确请求限定范围，而不是继续给全量结论。
4. 条件满足后，DA08 解释结果，DA10 交付表格与引用；DA04 保存实际调用、任务修订和程序资产。
5. 同类问题积累后，DA18 生成可复用 Skill/Preset 候选，DA11 做独立验证，DA12 按已有策略控制共享生效；运行需求可由 DA14 持续触发。

上述每一步都可从已有资产进入，返回前一步或替换实现。若只需要一次即席分析，无需创建持续任务、部署专用实例或扩充企业共享经验。
