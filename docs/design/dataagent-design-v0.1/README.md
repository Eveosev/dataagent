# DataAgent 分层设计草案 v0.1

本组设计将已有能力规划展开为模块及原子能力的输入输出、职责边界、调用入口和拟议代码目录，供后续讨论建设范围、组件实现与合作分工。目标是 Agent 基于可替换组件探索和组合，达到约定的端到端业务效果；业务场景可以沉淀为 Skill / Preset / Bundle，方法和中间流程允许调整。

本版统一依据[飞书规划](https://modelbest.feishu.cn/docx/TlN4dygs9oJR3Qx1FaictiPEn3c)的 revision 1022 及其[本地快照](../../research/dataagent-2026-11-02/sources/pluggable-dataagent-after-revision-1022.xml)。四组设计已分别发布为飞书文档，并在主规划 revision 1024 的“目标”后加入索引（发布批次与回执已删除）。本版尚未创建运行时代码。文中的包路径、类型名和注册描述均为拟议设计，尚未与 Mint/iface 做实现对比或兼容确认。

## 2. 模块定位

| 编号 | 模块 | 主定义所在文档 | 与其他模块的主要边界 |
| --- | --- | --- | --- |
| DA01 | 数据接入 | 数据层 / 01-ingestion | 建连接、读内容与源端结构；通用 SQL 执行归 DA07 |
| DA02 | 数据准备与探查 | 数据层 / 02-preparation | 结构恢复、画像与数据血缘；业务定义归 DA03 |
| DA03 | 业务语义与关系 | 数据层 / 03-semantics | 定义含义、规则、关系与物理映射；不代替实际执行 |
| DA04 | 任务轨迹与记忆 | 数据层 / 04-memory | 保存实际事件、任务修订、经验与程序资产；检索归 DA05 |
| DA05 | 召回检索 | 执行应用层 | 从表/列/值/语义/记忆/文档/组件等入口找候选；不承担证据存储或最终答案验证 |
| DA06 | 语义查询与计算计划 | 执行应用层 | 生成和修正计划、SQL/调用/表达式；通用程序生成复用 DA08.6 |
| DA07 | 计算执行 | 执行应用层 | 提交与执行、读取实际状态与结果、动作控制；不自己放宽授权或业务标准 |
| DA08 | 分析 | 执行应用层 | 方法规划、分析与解释；DA08.6 提供共享程序生成与修复 |
| DA09 | 预测、仿真与优化 | 执行应用层 | 在给定目标、假设和约束下推演；不自动把建议变成业务动作 |
| DA10 | 表格、可视化与交互 | 执行应用层 | 交付呈现与纠正定位；资产生效、写入和任务修订复用相应模块 |
| DA11 | 评测与验证 | 评测与治理层 | 检查业务效果与过程，记录范围与缺口；发布和授权另行判定 |
| DA12 | 治理与资产维护 | 评测与治理层 | 权限策略、资产版本、生效控制、变更影响与审计；不在每项能力前强加人工审批 |
| DA13 | 数据建模与物化 | 数据层 / 05-modeling | 定义物理模型和转换；生成、执行与验证分别复用 DA06/08、07、11 |
| DA14 | 持续运行与监控 | 持续运行与 FDE 交付扩展 | 触发、监控、等待恢复；作业提交/状态读取归 DA07.9 |
| DA15 | 动作契约 | 持续运行与 FDE 交付扩展 | 绑定业务动作与实现、声明执行要求、登记目录；不执行动作 |
| DA16 | 委托、审批与人在环 | 持续运行与 FDE 交付扩展 | 明确代表谁及可做什么，按策略批准或介入；证据充分不等于授权 |
| DA17 | 业务环境配置与协作上下文 | 持续运行与 FDE 交付扩展 | 环境默认配置、部署与子任务装配；本次任务真实修订归 DA04.5 |
| DA18 | 交付与交接 | 持续运行与 FDE 交付扩展 | 业务 Skill、组件组合、操作入口与交接；结果验证归 DA11，发布政策归 DA12 |

DA13 在数据层已完整定义，不在第四组重复展开。跨模块消费同一能力通过引用和端口完成，避免业务场景再维护另一套解析器、生成器、执行器或验证标准。

## 3. 跨层契约

基础类型以[数据层共享契约](../dataagent-data-layer-v0.1/06-shared-contracts.md)为本版定义来源；其他层按职责补充检索候选、计划、执行回执、分析结果、评测报告、策略决定、作业与交付等对象。跨层的具体交接及责任见[跨层契约与组合约定](cross-layer-contracts.md)。

统一调用形式是 `invoke(operation, input, CallContext) -> CapabilityResult<T>`。这只统一上下文和结果外壳，各能力仍有明确的业务参数与结果类型，不把全部调用压进任意字典。大数据通过受控引用传递，分页和作业通过后续读取入口继续；状态必须区分待输入、部分完成、处理中和失败。

文档先给出可讨论的语义契约；精确 JSON Schema、传输协议及生产部署选型在实现前进一步收敛。代码建议采用 Python 能力工作区、共享契约、端口与可替换适配器；不同层可独立发布，不能各自复制共享对象定义并逐渐分叉。

## 4. 组合方式

一个问题可能从值反查表列，再寻找业务规则；也可能直接复用已验证方法，先执行一小步再补语义。检索不足、计划不可执行、方法不适用或结果验证失败，都可以触发补数、换实现、修程序、重组子任务或澄清。四组文档的先后顺序不表示任务必须依次经过全部模块。

Agent 或 Skill 可以指导这些选择；Preset 可以提供默认组合和可替换点；业务目标、正式验收与权限边界保持明确。动态探索产生的有效程序和组合通过 DA04 保存，按 DA11 验证，在 DA12 对应策略下生效，再由 DA18 交付为可复用 Skill/Preset。

## 5. 阅读顺序

先阅读所关心层级的模块总表，确定建设和合作范围；随后查看原子能力契约及源码映射，判断哪些可直接复用、哪些需要独立实现或领域适配；最后用跨层交接和业务样例检查是否能完成端到端效果。细粒度目录是建设选择清单，不要求首版实现全部 434 项，也不要求每项单独发包或暴露成常驻 Agent 工具。
