## 7. 阶段 E：按批派工（Claude Code + crew）

### 7.1 把卡片变成 crew 任务单

字段名以 crew 的 `references/task-spec.md` 为准，对应关系：

| 任务单 | 取自 07 的卡 |
|---|---|
| 任务 ID | 卡号（如 `T10`） |
| 目标 | 卡的「目标」加「改法」 |
| 范围（scope） | 卡的「文件」列；写到目录的，指该目录下的源码与测试 |
| 验收命令（acceptance） | 卡的「命令」列，每条一项；命令前先 `source ~/Vibe/dataagent-private/p1.env` |
| 审核要点 | 卡的「验收」列，交给 codex |
| implementer | 卡的「执行」：dsh / zcode / auto |
| `dev_record` | `feishu-records.json` 的 `dev_records.<卡号>` |
| `--master` | `dataagent-<模块>-<卡号>-<日期>`，如 `dataagent-platform-T10-20261118` |

任务单写到 `.crew/specs/<卡号>.yaml`，派工前跑 `check`。给实现方的说明里写明：先读 07 里这张卡和 00 §2 的统一词汇；改动只在 scope 内；私有数据不进仓库。

### 7.2 每批的流程

1. 确认这批卡的依赖都已合入 `feat/p1-intake`。
2. 写任务单、`check`，把拆分和每张单的要点（目标、范围、验收、实现方、理由）给 payne 看。
3. payne 回「可以」后逐个 `dispatch <单> --yes --master <会话名>`，全部派完再 `wait <ID…> --timeout 540`，没完就继续 wait。
4. 用人话汇报每张卡：状态、几轮、验收、codex 结论和要点、warnings。卡在「待决定 / 失败 / 超时」时给 payne 选项（retry、换实现方、continue、放弃），他选了再做。
5. 通过的卡 `merge <ID>` 出计划给 payne 看，确认后 `merge --yes`，然后推送 `feat/p1-intake`（入口提示词已授权）。
6. 开下一批。
