## 附：第一批三条的细节与沟通稿（基线 agent-kernel@8439ec88）

### IF-01 MCP 工具的效果声明

现状（三层各管一段，中间断开）：

1. **Kernel（iface）**：`ToolEffect{Unknown, ReadOnly, SideEffect}`、`ToolContract::effect()`（`kernel/iface/src/tool.rs:141-156`），只由受信的嵌入实现在启动代码里声明；目前用在 Scheduler 的只读执行限制（`kernel/host/src/startup/trusted_tool.rs:402-404`：只读执行只能调 `ReadOnly` 工具）。
2. **Mint（cpmrt，TUI / `mint gui` / `mint run` 都走这里）**：MCP 工具的类型靠**工具名猜**（`mint/crates/mint-core/src/mcp/client.rs:738` `guess_kind_from_name`：名字含 search/list/get 算 Search，含 read 算 Read……），完全不看 MCP 标准的 `annotations.readOnlyHint`；`McpTool.meta` 预留了 `_meta["mint/tool"]` 语义类型（`mcp/types.rs:147`）但 `convert_tool_spec` 没用。审批按类型：Read/Search/Think 放行，写类按 `prompt_for_write`，其余问人（`approval.rs:143`）。DataAgent 的 `intake_start`、`intake_status`、`mapping_preview` 都猜成 Other，所以默认策略下全部要人确认、无人值守全部被拒（T50）。
3. **DataAgent**：只有 runtime 的 MCP 服务输出了 `readOnlyHint` 等注解（`dataagent_runtime/interfaces/mcp_server.py`），工作台和 operations 还没有（T12a 暂缓）。

要谈的核心是「谁有权声明」：MCP 规范里注解只是提示，服务可以谎报；Kernel 的原则是「模型或调用方不能授予只读」。候选：

| 方案 | 声明来源 | 可信度 | 改动 |
|---|---|---|---|
| A | 包清单（mint.toml 或 .mcp.json）按工具声明效果，安装时随签名包固定 | 安装期受信，与 `ToolEffect`「装配时声明」一致 | iface：声明格式与映射规则；Mint：加载器读清单 |
| B | 直接信运行期的 MCP `annotations` | 低（服务自报） | 只改 Mint |
| C | A 为准、B 作一致性校验（不一致按 Unknown 并告警） | 高 | A + 少量校验 |

建议 C。iface 侧的贡献：声明格式（复用 `ToolEffect`，不另造枚举）、MCP 注解到 `ToolEffect` 的映射表、只读工具的定义口径（与 `ToolEffect::ReadOnly` 注释一致：无外部可见变更、无回调写、无委托副作用）。Mint 侧：加载器读声明，映射到 `ToolKind`（审批）与 `ToolEffect`（Kernel）。

对接：郑达奇（`ToolEffect` 作者，泳道 pilotdeck-host）谈契约语义；pengyue.li（`mcp/client.rs` 主要提交人）谈 Mint 加载器。

### IF-02 调用元数据下发给 MCP

现状：Mint 调 `tools/call` 时 `_meta` 只带 `protocolVersion`、`clientInfo`、`clientCapabilities`、`progressToken`（`mint/crates/mint-core/src/mcp/types.rs:169-176`），没有会话、调用、回合。iface 的 `CallMeta{session_id, call_id, turn}`（`kernel/iface/src/types/mod.rs:7-11`）只在宿主内部。DataAgent T11a 的 `resolve_context()` 已按原名读 `_meta`，宿主不给时走本机兜底。

要定的：键名与形状。MCP 规范建议自定义键加前缀，Mint 已有 `mint/input`、`mint/tool` 的先例。建议 `_meta["agentcpm/call"] = {"session_id", "call_id", "turn"}`（与 iface `CallMeta` 同形），常量与说明放进 iface（如 `types` 模块的 MCP 绑定一节），Mint 下发。另需写明：只对宿主经 stdio 拉起的 MCP 服务可信；HTTP 远程 MCP 不能据此判定身份。

对接：luyaxi（`types` 主要提交人）、pengyue.li（Mint）。改动小，适合我们起草。
