# 04 验收方法与数据

> 输入：令才 Computer Use 数据集评估（盘点材料 `docs/dataagent-盘点材料/令才CU数据集-验收可用性评估.md`）；09-benchmark 计划（`docs/research/dataagent-2026-11-03/09-benchmark-plan.md` v0.3，§3a、§6、§7）；[00 术语与总览](<00 术语与总览.md>) §12、§13。
> 用在：[06 PRD](<06 PRD.md>) 的 P1 目标 G1.12–G1.15；[07 MVP 实施文档](<07 MVP 实施文档.md>) 的验收数据任务。

## 1 结论

1. **约束**：真实客户数据现在拿不到（payne 跟进）；令才、食品安全这类审核场景没有「对 / 错」的真值，令才只有一部分能由 QL 规则确定地判。
2. **做法**：不用单一准确率验收。分三层数据（L1 通用 / L2 真实流程 / L3 构造真值）、五种方法（确定性子集、可判定率、证据可核验、冻结版本回归、变异注入），各自报数，不合成一个分数。
3. **防过拟合**：令才做深，通用能力用公开 benchmark 多维验证，核心与领域包按三条硬规则分界（§5）。

## 2 三层数据

| 层 | 数据 | 真值 | 证明什么 | 不能证明什么 | 评测任务 |
|---|---|---|---|---|---|
| L1 通用能力 | 公开 benchmark | 有 | 能力在公开分布上的准确率与锚点准确率 | 在客户真实数据上的效果 | P1：B02 文档解析与 OCR、B03 字段抽取与锚点、B16 多源对齐与实体解析、B17 字段与模式映射；之后见 §6 |
| L2 真实流程 | 令才 Computer Use 数据集（私有）；以后的食品安全样例 | 无，只有弱标签 | 真实输入能接进来、映射得上、证据可追、版本冻结后结果稳定 | 业务结论对不对 | B17 私有子集；06 的 G1.13、G1.14 |
| L3 构造真值 | 以 L2 真实样本为底注入已知违规 | 有，由构造给出 | 已知类型的问题能检出、干净样本不误报 | 没构造过的问题类型；规则本身是否合理 | B19 |

另有 Mint 双端证据包和人的体验观察，不属于以上三层。

## 3 五种方法

| 方法 | 做法 | 指标 | 局限 |
|---|---|---|---|
| 确定性子集 | 判定交给能确定判的规则（令才的 QL 规则；食品安全用国标限值，如 GB 2760、GB 2762、GB 2763），被测系统只负责取数与映射 | 子集上与规则引擎结论一致率 | 只覆盖能确定判的部分 |
| 可判定率 | 规则需要的字段被接入并映射上的比例，规则因此能判的比例；前置与后置 QL 分开算 | 可判定率；缺口分类（报文缺失 / 空数组 / 目录未注册 / 名称不一致） | 能判不等于判对 |
| 证据可核验 | 每个接入值、每条结论引用的字段，机器回查到原始报文或文件里的原值 | 证据可核验率（应为 100%） | 只证明「有据」，不证明「据对」 |
| 冻结版本回归 | 固定组件、规则包、引擎版本，同一输入多次运行逐项比对 | 结果一致率；版本变化后的差异清单 | 只证明「变没变」 |
| 变异注入 | 以真实样本为底改一个或几个值，构造「应检出 / 不应检出」成对用例 | 变异检出率；干净样本误报率；漏检归因（接入 / 映射 / 规则） | 只覆盖构造过的违规类型 |

专家金标是唯一能衡量对错的数（Q2）。P1 不依赖它。

| 标签 | 旧规则版本的历史结论 16 通过 / 13 不通过；「规则2」结论 29 次全部不通过；两套在 16 次调用（8 张单据）上矛盾；人工金标 0 |

| 可用于 | 流程与报文格式验收；字段映射与接入质量验收（最有价值）；冻结版本回归基线；变异集的底样 |
| 不可用于 | 审核准确率；文档接入（发票已结构化，附件原件取不回） |

使用规则：

1. 数据留在原位，用 `private://lingcai-2026-10-28/<相对路径>` 引用；仓库、报告、飞书只出现聚合计数，不出现姓名、金额、单号、签名 URL。
2. 只有 2 个独立发票组：全部按回归集对待；同一组的样本及其变异不得跨切分；独立组到 10 个以上再设留出集。
3. 规则包与引擎版本在界面上只有名称，没有不可变标识；回归基线必须在重跑时记录实际版本与结果快照。

## 5 防过拟合

| 规则 | 做法 | 怎么检查 |
|---|---|---|
| 领域词不进核心 | 本体定义、定义页、规则、映射样例、skill、验收样例放领域包；核心包源码不出现领域词表里的词（报销、发票、采购、招待、差旅、食品等） | CI 词表检查；现有违例 `dataagent-workbench/src/dataagent_workbench/bootstrap.py:35` 的采购本体在 P1 移出 |
| 两次规则 | 进入核心的契约或能力至少两个领域用到；只有令才需要的放领域包；向 agent-kernel 提 PR 同样适用 | 评审清单一项 |
| 留出领域验收核心 | 新领域只写领域包，核心改动为 0 | 「新领域到第一个可验收结果的人时」「核心改动行数」两个数随每期报告 |
| 评测分层 | 核心指标用通用基准，领域指标用领域金标，分开报；核心指标不许靠调令才样本刷上去 | scorecard 分开两段 |
| 接口从 FDE 环推导 | 核心接口按「观察 → 识别 → 候选 → 核验 → 保存」定，不按报销单、发票这些概念定 | 设计评审 |

领域安排：

| 领域 | 角色 | 状态 |
|---|---|---|
| 令才报销审核 | 深度验证：L2 + L3 | 数据集可用；引擎重跑需地址与凭据 |
| 食品安全审核校对 | 第二领域：国标限值作确定性子集，检测报告、标签、许可证之间的批号、日期、项目与限值一致性做变异 | 等数据（payne 跟进，Q1） |
| 通用 benchmark | 多维 L1：文档、抽取、对齐、映射、关系发现、问数、金融数值推理 | 已有 14 个任务 3217 条用例，判分器只覆盖 B01–B04；新增 B16–B20 |
| 采购对账 | 不做（payne 11-16） | — |
