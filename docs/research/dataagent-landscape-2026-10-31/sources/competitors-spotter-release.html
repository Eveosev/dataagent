26.10.0.cl Release Notes

ThoughtSpot Cloud 26.10.0.cl is now available.

These release notes include information about new and enhanced features.

For information about previous releases, see Release history.

ThoughtSpot also provides weekly updates containing bug fixes and enhancements which are automatically deployed on customer instances. For details, see Weekly release notes.

New features and functionality

The latest release of ThoughtSpot Cloud contains several new and enhanced features.

The features described in these release notes may have one of the following statuses.

Feature statuses

Beta

Beta features are incomplete and may change before GA. They are enabled for select customers to collect feedback and have limited documentation. Beta features are disabled by default. Your administrator must contact ThoughtSpot support to enable them.

Early Access

Early Access features are complete and supported, but not yet enabled by default. You can try them before GA, with full documentation available. Early Access features are disabled by default. Refer to the feature documentation for how to enable them.

GA

General Availability (GA) features are usually enabled by default for all customers. They are fully supported. If the GA feature is not enabled by default, the process for enabling it is noted in the documentation.

For the Business User

Spotter Analyst builder GA

The Spotter Analyst builder is now generally available (GA). In this chat-based interface, you can describe the analyst you would like to use, and Spotter translates your requests into instructions for the agent. Spotter Analysts are also GA in this release.

For more information, see Spotter Analysts.

Spreadsheets GA

The spreadsheet interface puts a familiar, editable grid directly on your live data. Save your work as an Answer that stays searchable, shareable, and governed like anything else in ThoughtSpot.

  • Columns and formulas on live data: Build new metrics with 70+ built-in functions. Every formula runs as a live query and persists as governed logic your team can reuse.

  • Shape your view instantly: Sorting, filtering, conditional formatting, and text and number formatting help you focus on what matters, and are applied live on your data.

  • Save as a governed Answer: Your spreadsheet becomes a searchable, shareable object with security and lineage intact, never a disconnected export.

  • Built for real datasets: Scroll seamlessly through large result sets and switch to full-screen mode for focused analysis.

    For more information, see Spreadsheet.

Spotter connector marketplace GA

Spotter now features a browsable catalog with more than 100 third-party connectors, making it easier than ever to discover and add third-party data integrations. Every user can browse, search, and explore available connectors, including one-click options like Slack and Web Search, plus connectors for services like Microsoft Teams that guide you through setup. Your administrator or users with the CanManageSpotter privilege can add and configure connectors for your organization. If you don’t see a specific MCP server in the catalog, any MCP-compliant server can still be added manually. The Spotter marketplace connectors are available to all users in Spotter by selecting Settings > Connectors. This feature and the Can Manage Spotter privilege will be rolled out in the first weekly patch after the 26.10.0.cl release. For more information, see Spotter connector marketplace.

Charts added to the new charts library GA

The new charts library expands to add waterfall, pareto, funnel, and heatmap charts, bringing enhanced analytical flexibility and modernized styling across search, Spotter, and Liveboards. This release introduces support for multi-panel trellis and faceting modes, new multivariate axis configuration logic, and expanded customization options — including independent color controls for increment and decrement bars on Waterfall charts, refined gradient and label positioning on Heatmaps, and enhanced axis formatting on pareto charts. For more information, see Changes in 26.10.0.cl.

Command palette redesign

The command palette has a new, polished look and feel that introduces full support for light and dark modes, smooth open and close animations, and a cleaner layout with updated icons and filter chips. Search results now highlight matching terms for faster scanning, and improved loading and visuals make it easier to understand what’s happening as you search. The keyboard shortcuts and commands have not changed. For more information, see Command palette.

Faster chart rendering for all charts in Spotter answers Early Access

Spotter now uses progressive rendering to display charts instantly as soon as your query returns results, rather than waiting for the chart generation to complete. An initial chart appears immediately, then automatically updates in the background with refined styling and data-aware formatting — with a subtle indicator letting you know the enhancement is in progress. Any manual adjustments you make always take priority. The result is a noticeably faster and smoother experience when exploring data with Spotter. This feature now works with token and non-token-based answers. To enable this feature, contact ThoughtSpot support. For more information, see Progressive rendering.

For the Analyst

Liveboard contextual filtering Early Access

Liveboard creators can now scope filters and parameters to a specific tab or group, instead of applying them globally across the entire Liveboard. This makes it easier to build focused, information-dense Liveboards where you can analyze a specific area without inadvertently affecting unrelated visualizations. To enable this feature, contact your administrator.

When a Liveboard with tab or group filters is imported into a cluster where this feature is disabled, the scoped filters are removed on import.

For more information, see Liveboard contextual filtering.

Liveboards with column-security rules GA

The enhanced behavior of Liveboards built with column security rules is now generally available (GA). If users restricted by column security access the Liveboard, they can see and interact with the Liveboard filters and visualizations, but cannot edit the Liveboard as a whole. If such inaccessible columns are used as filters in the Liveboard, the Liveboard will no longer be blocked. Schedules now honor column security rules, and each recipient receives their own report based on their column security rule assignments.

For more information, see Column security rules on Liveboards.

For the Data Engineer

Spotter connector user group sharing GA

We’ve added more granular controls for sharing Spotter connectors in ThoughtSpot. Previously, if an administrator enabled a Spotter connector like Slack, it was shared with all users across all Orgs. Now, if you add a connector in the primary Org, you can choose whether to share it with certain users and groups, and it will be hidden by default from all other users and groups. You can still only add or edit connectors from the primary Org, but you can share connectors within any Org.

For more information, see Sharing a connector.

Liveboard dependency management Early Access

Admin users can now delete data model columns even if they’re in use on Liveboards. When a data model column that a Liveboard depends on is deleted, ThoughtSpot now detects the impact and shows you exactly what’s broken instead of displaying a generic error or silently failing. To enable this feature, contact ThoughtSpot support. For more information, see Liveboard dependency management.

Writeback for Snowflake Beta

Writeback with input tables allows you to create and edit tables directly in ThoughtSpot, where you can add new columns and update values. Data is saved back to your cloud data warehouse so you can use these tables across Answers and Liveboards. Currently, we support Snowflake cloud data warehouses. This feature supports planning, and operational workflows, removing the need for spreadsheets or manual uploads. Only users with edit permissions can make changes, and all edits are tracked for governance. To enable this feature, contact ThoughtSpot support.

For more information, see Writeback.

Muze Studio AI Beta

Muze Studio now includes an AI chat assistant that lets you build and refine custom charts using natural language. Simply describe the visualization you want, or ask follow-up questions to iterate on it, and the AI generates the configuration for you directly inside the Muze Studio editor. A built-in "Show work" timeline lets you trace each step the AI took, giving you full visibility into how your chart was constructed. To enable this feature, contact ThoughtSpot support. For more information, see Use AI chat to create and refine charts.

Publishing from object lists GA

Publishing, and publishing from object lists are now generally available (GA). You can now publish, unpublish, and manage the publishing state of Answers, Liveboards, and Models directly from the list page view without having to open each object individually.

The Publish, Unpublish, and Manage publishing options are available in the row-level action menu on the Answers, Liveboards, and Data Workspace list pages. The publish and unpublish options allow you to select target Orgs, handle dependents, and confirm the action.

Publishing is a multi-Org feature. These actions are only visible in multi-Org environments where object publishing is enabled. You must be in the primary Org and be a cluster administrator to see the publish and unpublish actions.

For Models specifically, the publish action is not available for objects authored by a superuser or system user.

For more information about publishing objects across Orgs, see Publishing objects between Orgs.

Connection-level query timeout GA

You can now set query timeout in the Advanced Config setting when you add Connections. You can define how many seconds a query should run for before it automatically times out.

Act as user Early Access

ThoughtSpot administrators can now impersonate a specific user to troubleshoot issues directly, without requiring screen shares or shadow accounts. To initiate a session, the administrator first requests the user to configure their Act as user preferences on their profile page, where the user sets the permitted time window for impersonation. Sessions expire automatically at 60 minutes, and the administrator can end the session at any time using the Exit session button. The user receives email notifications when a session starts and ends. All actions taken during the session are captured in audit logs.

This feature is available for customers with the new Admin Portal enabled. Administrators can enable it from Feature Management > Early Access.

For more information, see Act as user.

Databricks Metric Views integration Early Access

Databricks Metric Views integration is now available in ThoughtSpot. This integration allows you to connect directly to Metric Views defined in Databricks and use them to automatically create Models in ThoughtSpot. You can import Metric Views, including metrics, formulas, and column metadata, and immediately use them for building Liveboards, running queries, analytics, and Spotter. Users with Can manage data privileges can manage and resync Metric Views as needed to reflect changes made in Databricks. To enable this feature, contact your administrator.

For more information, see Integrate Databricks Metric Views.

Data workspace page GA

The new Data workspace page is now generally available (GA). It now uses a modernized object table, making it easier to find, filter, and manage your data objects in one place.

For more information, see Data workspace.

Secure suggestions in saved filter values Beta

ThoughtSpot now enforces row-level security (RLS) on saved filter values in Answers and Liveboards. When a filter chip displays values from a column marked as Secure Suggestions in the data model, ThoughtSpot checks whether the current user has RLS access to those values before displaying them.

When filter values are cleared due to RLS enforcement, the user still sees data, but only the rows their RLS policy permits. An empty filter chip on a secured column does not mean no data; it means the saved filter values were not applicable to this user and the RLS policy is the active constraint.

To enable this feature, contact ThoughtSpot support. For more information on secure suggestions and RLS, see Secure suggestions in saved filter values.

Object IDs in template variables Beta

You can now define object IDs for variables in TML or the API. Object IDs now support multi-tenant objects. Use object IDs in tandem with GUIDs that identify objects in TML. You can use object IDs to identify objects that you export in TML and import to other Orgs, removing the need to completely recreate objects between Orgs. For more information, see model in TML for Models and db_table in TML for tables.

Amazon Athena driver upgrade GA

We have upgraded the Amazon Athena driver to version 3.8.0.

For more information, see Cloud data warehouse driver details for connections.
