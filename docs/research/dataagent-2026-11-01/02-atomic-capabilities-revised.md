# DataAgent 模块与原子能力简稿

按**数据层、执行应用层、评测和治理层**讨论。一级是模块大类，二级是能力组，三级是可选择和发布的细分能力；现阶段只说明作用和边界，不定义接口。

原子能力围绕一个明确目的设计，同一能力可以有多种后端或算法实现。用户、Agent 或平台可以组合出 Preset / Bundle，例如“不规则表格处理”“企业问数”。循环、重试、任务路由等由组合流程安排。

三级编号形如 `DA01.4.1`。同一能力的算法或执行后端可以作为适配实现，不必每种实现都重复发布一个包。

二级能力组是共享对象、验收判据和评测集的范围；三级能力可单独选择和发布；适配实现只替换后端或算法，不改变能力的输入输出与边界。发布单元不等于 Agent 可见的工具：Agent 默认面对 Preset 和少量能力入口，三级能力和适配实现由组合流程按需选择，避免把上百项能力全部暴露为工具。

| 层次 | 一级模块 | 关注点 |
| --- | --- | --- |
| 数据层 | DA01 数据接入；DA02 数据准备与探查；DA03 业务语义与关系；DA04 任务轨迹与记忆 | 数据如何进入、被理解、存储和积累 |
| 执行应用层 | DA05 召回检索；DA06 语义查询与计算计划；DA07 计算执行；DA08 分析；DA09 预测、仿真与优化；DA10 表格、可视化与交互 | 根据任务检索、计算并交付 |
| 评测和治理层 | DA11 评测与验证；DA12 治理与资产维护 | 是否正确、可用、可共享，如何更新 |
| 广义扩展 | DA13 数据建模与物化；DA14 持续运行与监控 | 构建可持续使用的数据集，并在无人发起时保持运行 |

狭义 DataAgent 聚焦“问题到答案”，以 DA01–DA12 中的只读能力为主；广义 DataAgent 还要构建和维护数据与语义资产、写回业务系统、持续运行，涉及的能力见第四章。业务记忆与自进化闭环见第五章，插件、领域包与 Preset 的组织方式见第六章。

## 〇、共享对象

各能力之间传递以下对象。这里只约定对象及必须携带的信息，不规定字段名和序列化格式；后续可作为契约包发布，使不同实现、不同伙伴提供的能力可以组合。所有对象都有稳定标识和版本，数据血缘、语义血缘和产物来源使用同一套标识。

| 对象 | 必须携带的信息 | 主要产生 | 主要使用 |
| --- | --- | --- | --- |
| 数据引用 | 来源与连接、表/文件/接口位置、快照或 as-of 时点、访问身份 | DA01、DA02、DA13 | DA05–DA08、DA11 |
| 结构信息 | 字段、类型、键、画像引用，以及源端能力（是否支持 SQL、过滤、聚合、分页） | DA01.2、DA02.4 | DA05、DA06 |
| 语义对象 | 类型（实体、指标、维度、规则、关系、时间与单位）、定义、物理映射、版本、生效时间、作用域、状态（草案/候选/认证/废弃）、来源 | DA03 | DA05、DA06、DA11 |
| 计算计划 | 计算目标、绑定的语义版本、各步执行目标与表达、步骤依赖、假设与歧义处理 | DA06 | DA07、DA11.2 |
| 执行结果 | 结果数据或引用、执行状态、完整性（分页、截断、采样）、实际输入、血缘缺口、成本 | DA07 | DA08–DA11 |
| 证据引用 | 结论所依据的结果、语义、文档段落与记忆及其版本；区分已验证结论与假设 | DA05、DA08 | DA10、DA11 |
| 任务上下文 | 本任务固定的数据与语义版本、已选经验、权限范围、任务修订号 | DA04.5 | 同一任务内的所有 Agent 与能力 |
| 记忆条目 | 类型、内容、适用条件、作用域、状态、来源轨迹、验证记录、失效条件 | DA04 | DA05.3、DA06、DA08 |
| 变更请求 | 目标对象与当前版本、作用域、变更内容与差异、影响范围、验证要求、执行回执、撤销方式 | DA10.4、DA12.7 | DA07.4、DA12.5 |

## 一、数据层

### DA01｜数据接入

连接企业来源或导入现场文件，保留原始结构。

| 二级能力组 | 三级细分能力 | 作用与边界 |
| --- | --- | --- |
| DA01.1 来源连接 | DA01.1.1 数据库连接<br>DA01.1.2 API 连接<br>DA01.1.3 MCP 连接 | 接入数据库、API、MCP，管理连接与身份引用。 连接成功不代表来源支持执行 SQL。 |
| DA01.2 结构读取 | DA01.2.1 数据库 Schema 读取<br>DA01.2.2 API 结构读取<br>DA01.2.3 MCP 工具能力探测 | 获取表列、类型、键、API 字段及源端能力。 不推断业务含义。 |
| DA01.3 数据读取 | DA01.3.1 条件读取<br>DA01.3.2 分页读取<br>DA01.3.3 采样读取 | 按字段、条件、分页或采样读取数据。 SQL 执行统一使用 DA07.1。 |
| DA01.4 文件解析 | DA01.4.1 规整 Excel 解析：提取明确表头的单表或多 sheet 表<br>DA01.4.2 不规则 Excel 提取：从混合布局中恢复逻辑表<br>DA01.4.3 CSV/TSV 解析：处理分隔符与编码<br>DA01.4.4 JSON/JSONL 解析：保留嵌套记录<br>DA01.4.5 文本型 PDF 解析：读取文字与版面位置 | 读取 Excel、CSV、JSON 和 PDF 文本层，保留 sheet、公式、坐标等结构。 不规则 Excel 入口复用 DA02 的表块检测和结构恢复；PDF 表格提取也复用 DA02，扫描件先使用 OCR。 |
| DA01.5 OCR | DA01.5.1 扫描 PDF OCR<br>DA01.5.2 图片 OCR | 识别扫描 PDF 和图片中的文字、位置。 保留识别不确定性，不纠正业务数字。 |
| DA01.6 资产目录登记 | DA01.6.1 资产目录登记<br>DA01.6.2 维护者与使用条件登记<br>DA01.6.3 更新承诺与新鲜度登记 | 记录资产位置、责任人、适用范围及更新承诺。复用现有目录；登记承诺与实际新鲜度分别记录。 |
| DA01.7 增量与事件接入 | DA01.7.1 游标/水位增量读取<br>DA01.7.2 CDC/事件接入<br>DA01.7.3 迟到与重复事件处理 | 持续接收变化，保留顺序、水位及补采位置。依赖来源能力；任务调度和通用重试复用平台。 |

文件入口按布局选择：**规整 Excel** 可以直接读取明确表头的单表或多表；**不规则 Excel** 需要识别表块并恢复结构。单 sheet 也可能包含多个不规则表，多个 sheet 也可能全部规整。跨表业务 Join 由关系建模与查询完成，不由解析器决定。

`DA01.4.2` 是面向文件任务的组合入口，内部调用 `DA02.1`、`DA02.2`；这些底层处理只维护一套。“不规则表格分析”Preset 再组合这个入口、质量检查、查询或分析能力。

### DA02｜数据准备与探查

把现场数据整理成可分析的表，并探查其结构与分布。

| 二级能力组 | 三级细分能力 | 作用与边界 |
| --- | --- | --- |
| DA02.1 表格区域识别 | DA02.1.1 工作簿表块检测<br>DA02.1.2 文档页面表格检测 | 从页面或 sheet 中定位一个或多个表块。 不判断业务对象是什么。 |
| DA02.2 表格结构恢复 | DA02.2.1 多行表头恢复<br>DA02.2.2 合并单元格展开<br>DA02.2.3 明细/合计行识别<br>DA02.2.4 跨页续表拼接 | 识别多行表头、合并单元格、分节、重复表头、合计行及续表结构。 保留原值；不能确认的拼接保留待确认状态。 |
| DA02.3 数据结构转换 | DA02.3.1 表格转置<br>DA02.3.2 宽长表转换<br>DA02.3.3 嵌套字段展开<br>DA02.3.4 同结构表追加 | 按指定规则转置、宽长转换、展开嵌套或拼接表格。 不替用户决定跨表业务关系。 |
| DA02.4 数据画像 | DA02.4.1 表结构画像<br>DA02.4.2 字段取值画像<br>DA02.4.3 字段类型推断<br>DA02.4.4 时间角色识别<br>DA02.4.5 记录粒度识别 | 统计结构、空值、基数、分布，推断字段类型、时间和记录粒度。 推断是候选，不直接成为业务定义。 |
| DA02.5 Join 关系发现 | DA02.5.1 键关系发现<br>DA02.5.2 取值覆盖匹配<br>DA02.5.3 Join 基数探查 | 根据键、覆盖率、基数和历史查询寻找关联候选。 业务关系确认归 DA03。 |
| DA02.6 数据清洗 | DA02.6.1 重复记录处理<br>DA02.6.2 类型转换<br>DA02.6.3 取值标准化<br>DA02.6.4 缺失值处理 | 按选定规则执行去重、类型转换、标准化和缺失处理。 保留原件和变换记录，不静默补造事实。 |
| DA02.7 数据血缘 | DA02.7.1 源端血缘导入：接入数据目录、ETL 或数据库已有血缘<br>DA02.7.2 SQL 血缘提取：解析表、视图和列的读取与派生关系<br>DA02.7.3 转换血缘采集：记录文件处理、代码和数据转换的来源及去向<br>DA02.7.4 数据血缘维护：保存和更新带版本的表级、列级依赖 | 说明数据从哪里来、经过什么处理。区分静态推断与实际执行记录；动态 SQL、存储过程或未覆盖的代码需标注缺口，不据此推断业务口径。 |
| DA02.8 文档加工 | DA02.8.1 章节/表格切分<br>DA02.8.2 原文引用锚点维护 | 将解析后的文档整理成保留上下文和原文位置的检索单元。复用 DA01 解析，不承担检索或业务结论判断。 |
| DA02.9 结构变化适配 | DA02.9.1 Schema 差异检测<br>DA02.9.2 接口兼容检查<br>DA02.9.3 字段映射修订建议 | 识别字段、接口及编码变化，判断既有读取和映射是否失效。修订建议不自动改变业务定义。 |
| DA02.10 修复建议与复核 | DA02.10.1 修复方案生成<br>DA02.10.2 修复前后验证<br>DA02.10.3 复核反馈转修复规则 | 根据质量问题提出方案，将接受、驳回和修改原因沉淀为有范围的规则。执行复用 DA02.6，验证复用 DA11，不自动覆盖原数据。 |
| DA02.11 历史数据保留 | DA02.11.1 文件/查询结果快照保存<br>DA02.11.2 源端 as-of/快照引用 | 保留可重算数据或有效的源端历史引用。仅有时间戳、digest 或最新数据不能保证历史重现。 |
| DA02.12 文档信息抽取 | DA02.12.1 按目标结构抽取字段<br>DA02.12.2 表单/单据键值抽取<br>DA02.12.3 抽取结果原文锚定 | 从合同、单据、病历等文档中按指定结构抽取字段和记录，形成可入表的数据。复用 DA01 解析与 OCR；每个值关联原文位置和置信度，低置信结果保留待确认，不补造缺失值。 |

### DA03｜业务语义与关系

维护业务对象、指标、规则及其与物理数据的对应关系。

| 二级能力组 | 三级细分能力 | 作用与边界 |
| --- | --- | --- |
| DA03.1 实体建模 | DA03.1.1 实体类型定义<br>DA03.1.2 实体属性定义<br>DA03.1.3 对象状态定义 | 定义客户、订单等实体及其属性、状态和粒度。 不等同于物理表定义。 |
| DA03.2 身份对齐 | DA03.2.1 编码映射<br>DA03.2.2 别名匹配<br>DA03.2.3 跨源实体匹配 | 识别跨系统的同一对象，维护编码和别名映射。 不直接覆盖业务主数据。 |
| DA03.3 关系建模 | DA03.3.1 实体关系定义<br>DA03.3.2 Join 规则定义<br>DA03.3.3 时态关系定义 | 表达实体关系、合法 Join、基数、时态和租户条件。 使用探查候选，但不把值重合直接认作合法关系。 |
| DA03.4 指标与规则定义 | DA03.4.1 指标公式定义<br>DA03.4.2 维度层级定义<br>DA03.4.3 业务规则定义 | 定义指标公式、维度、业务规则及适用范围。 不执行查询；未经确认的定义保留草案。 |
| DA03.5 时间与单位定义 | DA03.5.1 业务时间定义<br>DA03.5.2 财务日历定义<br>DA03.5.3 单位换算定义 | 定义业务时间、财务日历、币种、单位及换算规则。 实际计算由执行能力完成。 |
| DA03.6 语义映射与存储 | DA03.6.1 业务语义存储<br>DA03.6.2 语义与表列映射<br>DA03.6.3 语义与 API/文档映射 | 保存业务定义及其物理实现、说明来源，连接业务语义血缘与数据血缘。映射注明版本和适用范围；映射到某列不等于业务定义已经验证。 |
| DA03.7 业务语义血缘 | DA03.7.1 指标依赖提取：识别派生指标对基础指标、维度和时间口径的引用<br>DA03.7.2 规则依赖提取：识别指标、规则对其他规则及例外定义的引用<br>DA03.7.3 语义血缘维护：按定义版本保存和更新依赖 | 说明业务定义依赖什么，物理实现通过 DA03.6 关联。实体间“客户拥有订单”等关系仍归 DA03.3，不作为派生血缘。 |
| DA03.8 历史口径解析 | DA03.8.1 业务生效时间解析<br>DA03.8.2 指定时点语义版本解析 | 选择历史时点适用的定义，区分业务生效时间与系统记录时间。历史计算还需对应数据和程序版本。 |
| DA03.9 语义导入与冷启动 | DA03.9.1 外部语义层导入：读取 dbt、MetricFlow、Cube、BI 数据集等已有定义<br>DA03.9.2 历史口径挖掘：从历史 SQL、报表、Excel 模板和公式中反推指标、过滤与 Join<br>DA03.9.3 语义草案生成：结合结构、画像、文档和领域模板生成实体、指标与关系草案<br>DA03.9.4 待确认项排序：按影响范围和不确定性列出需要业务确认的定义 | 在没有现成语义层时尽快形成可用语义。产出均为草案，确认后按 DA12.5 生效；导入保留来源和无法转换的部分。 |
| DA03.10 语义冲突识别 | DA03.10.1 定义冲突检测：同名异义、异名同义、口径重叠<br>DA03.10.2 冲突说明与协调方案：并存、按作用域区分或合并 | 发现不同部门、来源或版本之间的定义冲突，并给出可选方案。不自动裁决认证口径；结论以作用域或新版本表达。 |

数据血缘记录“订单表金额列 → 收入汇总列”；业务语义血缘记录“净收入 → 已支付销售额、有效退款额及其口径”。DA03.6 把业务定义关联到实现表列。两种血缘可共用底层存储，但分别保留关系类型和版本：迁表可能只改变数据血缘，调整退款规则可能只改变业务定义及其依赖。

### DA04｜任务轨迹与记忆

区分原始执行记录、可复用经验和分析产物，使任务积累可以被后续任务使用。

| 二级能力组 | 三级细分能力 | 作用与边界 |
| --- | --- | --- |
| DA04.1 任务轨迹存储 | DA04.1.1 任务事件记录<br>DA04.1.2 查询/工具调用记录<br>DA04.1.3 用户纠正记录 | 保存任务中的问题、计划、工具调用、SQL、结果引用和用户纠正。 可复用 AgentOS 轨迹存储；完整轨迹不等于可信经验。 |
| DA04.2 任务经验提炼 | DA04.2.1 成功查询提炼<br>DA04.2.2 分析方法提炼<br>DA04.2.3 失败经验提炼<br>DA04.2.4 流程模板提炼：从多次成功的同类任务中提炼分析流程或 Preset 配置候选 | 从轨迹提炼有效查询、分析方法、失败经验、可复用流程及其适用条件。 生成候选经验，不自动升级为企业业务规则；模板保存使用 DA04.4.3。 |
| DA04.3 记忆存储 | DA04.3.1 个人记忆存储<br>DA04.3.2 任务共享记忆存储<br>DA04.3.3 企业经验存储 | 按用户、任务或企业范围保存已选择的经验和历史结论。 管理存储与作用域；如何找回交给 DA05。 |
| DA04.4 分析资产存储 | DA04.4.1 查询/代码资产保存<br>DA04.4.2 模型资产保存<br>DA04.4.3 报表/模板资产保存<br>DA04.4.4 产物来源关联：记录结果、模型和报表使用的数据、语义、代码与参数 | 保存 SQL、代码、模型、报表及可复用模板，关联数据和语义版本。使用 MintHub 或现有资产存储；产物来源引用已有血缘，不另建一套依赖图。 |
| DA04.5 任务上下文 | DA04.5.1 任务上下文创建：固定数据与语义版本、已选经验和权限范围<br>DA04.5.2 子任务上下文派发：按子任务裁剪需要的引用与摘要<br>DA04.5.3 任务修订同步：口径或数据变化时生成新修订，并使旧结果失效 | 让同一任务内的多个 Agent 使用一致的口径与数据版本。只传引用和必要摘要，不复制全部轨迹；子 Agent 不能各自修改口径，修订经 DA10.4 发起。 |
| DA04.6 经验验证与晋升 | DA04.6.1 候选经验验证：在相关样本上回放比较<br>DA04.6.2 作用域晋升：个人、团队、企业逐级生效<br>DA04.6.3 冲突与污染检查：与认证语义、已有经验及其他用户纠正比对<br>DA04.6.4 经验失效与淘汰：数据或语义变更、出现反例或长期未用时降级 | 决定哪些候选经验可以进入哪个范围。晋升到团队或企业范围须有验证记录，验证复用 DA11.4；与认证语义冲突时不覆盖，转 DA03.10 或 DA12.3 处理。 |

业务关系、物理映射和指标依赖在 DA03 表达；“哪次任务用了哪个指标、生成了哪份报表”等使用关系随 DA04 记录并引用同一语义对象。原始轨迹与提炼记忆可以共享存储，逻辑上区分用途。

记忆状态依次为：原始轨迹 → 候选经验 → 已验证 → 已发布（个人/团队/企业）→ 失效。每次状态变化保留来源轨迹和验证记录；召回时 DA05.3 按状态和作用域过滤，候选经验只能作为参考，不能当作认证口径使用。

多 Agent 协作时，由 DA04.5 创建任务上下文，共享任务指定的数据与语义版本、已选经验及相关引用；子 Agent 按子任务检索并传递必要上下文，避免把全部轨迹复制给每个 Agent。一个子 Agent 发现口径需要调整时，形成新的任务修订，所有子 Agent 按新修订继续。

### DA06｜语义查询与计算计划

把用户问题转成符合业务语义、数据结构和后端能力的可执行计算。NL2SQL 是其中一条路径；也可以生成业务 API/MCP 调用、领域函数调用或计算表达式。

| 二级能力组 | 三级细分能力 | 作用与边界 |
| --- | --- | --- |
| DA06.1 计算需求解析 | DA06.1.1 指标与维度绑定<br>DA06.1.2 时间与过滤解析<br>DA06.1.3 计算歧义识别<br>DA06.1.4 澄清问题生成：针对影响结果的歧义给出问题和候选选项 | 识别计算目标、业务对象、条件和结果粒度。所需数据、语义和函数由 DA05 召回。只对影响结果的歧义发起澄清；可以按明确标注的默认假设先算，用户回答后更新绑定。 |
| DA06.2 业务语义编译 | DA06.2.1 指标计算展开<br>DA06.2.2 关系与约束展开 | 将已有指标、规则、关系和单位展开为计算步骤。物理实现可以是表列、业务接口或函数，不临时创造业务定义。 |
| DA06.3 执行表达生成 | DA06.3.1 单表 SQL 生成<br>DA06.3.2 多表 SQL 生成<br>DA06.3.3 SQL 方言转换<br>DA06.3.4 API/MCP 调用生成<br>DA06.3.5 函数调用与表达式生成 | 根据目标后端生成 SQL、接口参数、函数调用或表达式；需要 Python 等程序时复用 DA08.6，不另建代码生成能力。不执行，只使用已知接口和可用运行环境。 |
| DA06.4 计算计划修正 | DA06.4.1 语法与参数修正<br>DA06.4.2 执行错误修正<br>DA06.4.3 计算逻辑修正 | 根据反馈修改执行表达或计划。不能静默改变口径；修改后重新检查，迭代次数由流程控制。 |

DA06 与 DA07 合起来，可以视为一个**面向业务语义的计算引擎**：前者规划和编译，后者执行。这样既支持数据库查询，也支持“调用业务接口取数，再通过函数或本地表达式计算”。具体接口定义后续再定。

### DA07｜计算执行

执行已选定的 SQL、接口、函数、代码或表达式。同一能力按场景适配企业端与本地环境。

| 二级能力组 | 三级细分能力 | 作用与边界 |
| --- | --- | --- |
| DA07.1 `sql_execute` | DA07.1.1 企业 SQL MCP/API 执行适配<br>DA07.1.2 数据库驱动执行适配<br>DA07.1.3 本地 DuckDB 执行适配 | 将 SQL 提交给指定执行后端，取回结果及执行状态。 不生成 SQL；后端必须实际支持 SQL。 |
| DA07.2 `code_execute` | DA07.2.1 本地 Python 执行<br>DA07.2.2 远程沙盒代码执行 | 在指定环境执行 Python 等分析代码。 依赖现有运行环境和沙盒，不负责选择分析方法。 |
| DA07.3 `function_call` | DA07.3.1 本地函数调用<br>DA07.3.2 远程领域函数调用<br>DA07.3.3 业务 API/MCP 调用 | 执行已绑定参数的函数或接口调用并获取结果。限于声明能力和授权范围；有写入副作用的调用走 DA07.4 的变更控制。 |
| DA07.4 变更写入 | DA07.4.1 本地文件/数据集变更应用<br>DA07.4.2 企业 API/MCP 写回<br>DA07.4.3 写入回执与状态核对 | 将已确定的变更写到指定目标，保留请求标识、旧值/版本和结果。只读 SQL 后端不能承担写回；部分成功须逐项说明，不能因工具返回成功就认定完成。 |
| DA07.5 `expression_execute` | DA07.5.1 标量表达式计算<br>DA07.5.2 表数据表达式计算 | 使用指定表达式引擎完成算术、条件、过滤或聚合。只支持明确的算子、类型和函数；任意代码使用 DA07.2。 |
| DA07.6 `plan_execute` | DA07.6.1 多步计算执行<br>DA07.6.2 中间结果衔接 | 按已确定的依赖顺序调用 SQL、API、代码、函数或表达式执行器，传递中间结果并记录各步状态。固定计算计划可做成复合能力；开放式检索、重规划和业务审批仍由 Agent/Preset 组织。 |

`sql_execute` 是一个可发布能力，内部可按执行场景选择适配器：

| 场景 | 执行方式 |
| --- | --- |
| 企业提供 SQL MCP/API | 通过支持 SQL 的工具或接口提交查询，轮询或直接取回结果。 |
| 企业允许直连数据库 | 通过数据库驱动执行，使用对应身份与方言。 |
| 端侧文件分析 | 将准备好的文件表挂载到本地 DuckDB，再执行查询。 |

执行目标由连接能力和任务配置约束，DA06 生成对应计划；方言、接口参数和表达式生成归编译环节，DA07 处理提交、异步状态、结果读取、分页、超时及取消。DA01.3 负责来源数据读取适配；当业务接口作为计算计划的一步时，DA07.3 复用相同连接和读取实现，不另造一套接口适配。

例如“各地区净收入”：SQL 后端可编译为聚合查询；业务系统若仅提供销售额、退款额接口，则分别调用接口，再用表达式计算差额。两条路径都必须对齐时间、币种、粒度和分页完整性；业务 API 已经聚合的数据，不一定支持任意维度拆分。

只有取数 API 时，也可以完成接口本身不提供的计算。例如“订单金额最大值”：DA06 规划 API 取数及本地求最大值，DA07.3 调用接口，DA08.6 生成 Python（如 `max(amounts)`），DA07.2 执行并返回结果。模型负责生成程序，计算由运行环境完成；同一计划也可以选择本地 SQL 或表达式执行。必须取全问题范围内的数据，明确金额类型、空值和空集处理；接口仅返回样本或部分分页时，只能报告已获取范围的最大值。

执行时将可获取的查询、实际输入输出、执行状态和版本记入 DA04 轨迹，供 DA02.7 采集血缘。MCP 只返回结果而不暴露内部处理时，保留已知来源并注明缺口，不假定已获得完整列级血缘。

### 对话纠正怎样即时生效

对话消息到达 → DA10.4 识别纠正并定位对象/范围 → 检查权限和必要验证 → 更新目标 → 使受影响状态、缓存和结果失效并续算 → 向用户回显修改范围及写入状态。模糊反馈先追问，明确修正不必等离线反馈流程。

| 用户表达 | 当前任务动作 | 持久化动作 |
| --- | --- | --- |
| “这里要用支付时间，改完重算” | 更新任务时间绑定，重新生成/检查查询，重算结果。 | 记录纠正轨迹；默认只对本任务生效，不覆盖企业指标。 |
| “以后我问收入，默认排除测试单” | 当前问题相关时立即应用。 | 写个人记忆；与企业口径有冲突时保留明确标注，不能静默替代认证指标。 |
| “把这个指标定义更新为扣除退款，团队后续都用它” | 可先在任务内按新定义计算。 | 有共享修改权限且验证通过时创建新语义版本并生效；否则保留候选修订，说明未发布原因。 |
| “把上传表格中这三行编码改成 A01” | 定位原行，修改派生工作副本并验证相关结果。 | 保存新文件/数据版本及差异，保留原件。 |
| “把 CRM 中该客户等级改为 A” | 识别企业系统写操作和具体记录。 | 检查写权限和当前记录版本，通过 DA07.4 写回并核对；受企业审批约束时进入对应流程。 |

任务状态、个人记忆、共享语义和企业记录是不同写入目标，不应一次纠正全部改写。用户说“这里错了”只提供错误信号；说清修正对象和方案后才能形成具体变更。若旧计算仍在运行，取消或标记失效，防止旧结果覆盖新结果；多 Agent 按 DA04.5 的同一任务修订继续，不能各自沿用旧口径。

写入后关联原始纠正、变更前后版本和执行回执（DA04）；更新相关检索索引/缓存，并对本次会话保证读取已写入内容或明确提示尚在刷新。撤销优先恢复旧任务/资产版本；对已发生的企业动作检查源系统撤回或补偿能力，不能承诺任意写入可回滚。

## 四、广义扩展

广义 DataAgent 与狭义的差别不在功能数量，而在三处变化：任务内状态成为跨任务资产，只读变为写入，一次调用变为持续运行。前几章已有的广义能力如下；DA13、DA14 为新增模块。

| 变化 | 已有能力 | 新增能力 |
| --- | --- | --- |
| 资产化 | DA01.6 资产目录登记；DA02.7 数据血缘；DA03.6–DA03.10 语义存储、血缘、冷启动与冲突；DA04.4、DA04.6 分析资产与经验晋升；DA12.2 资产版本；DA12.9 跨租户沉淀 | DA13 数据建模与物化 |
| 写入 | DA02.10 修复建议；DA07.4 变更写入；DA12.5 交互变更控制；DA12.7 变更计划 | — |
| 持续运行 | DA01.7 增量与事件接入；DA02.9 结构变化适配；DA12.3 反馈与更新建议；DA12.8 配置调优 | DA14 持续运行与监控 |

### DA13｜数据建模与物化

在没有现成数据库时，把来源数据整合为可持续查询的数据集。

| DA13.1 目标模型设计 | DA13.1.1 主题/维度模型设计<br>DA13.1.2 数据契约定义：字段、约束、粒度、新鲜度承诺 | 根据业务语义和来源结构设计目标表及其契约。模型与 DA03 的实体、指标对应；设计结果是草案，确认后生效。 |

## 五、业务记忆与自进化

自进化指系统根据使用记录持续调整可复用的经验和配置，并能证明调整后效果变好。闭环如下：

任务执行 → DA04.1 记录轨迹与纠正 → DA04.2 提炼候选经验和流程模板 → DA04.6 回放验证并按作用域晋升 → DA05.3 在后续任务中召回 → DA11.6 度量效果 → DA12.8 调整 Preset 配置。

| 可进化对象 | 来源 | 生效前的检查 |
| --- | --- | --- |
| 个人偏好与默认假设 | 用户明确表达、DA10.4 纠正 | 与认证语义冲突时标注，不替代认证口径 |
| 已验证查询与分析方法 | DA04.2.1、DA04.2.2 | DA04.6.1 回放验证 |
| 语义草案与修订 | DA03.9、DA10.4、DA12.3 | 业务确认，DA12.5 生效控制 |
| 流程模板 | DA04.2.4 | 在同类样本上回放，DA11.4 回归通过 |
| Preset 配置 | DA12.8 | DA11.4 回归通过，灰度生效，可回退 |
| 领域包内容 | DA12.9 | 租户授权、脱敏，领域包维护者审阅 |

防止记忆污染：单个用户的纠正默认只在个人或本任务范围生效；晋升到团队或企业范围须有验证记录；长期未用、出现反例或依赖的数据与语义已变更的经验会降级。没有 DA11.6 的度量，不能声称系统在进化。

## 六、插件、领域包与 Preset

目的是让伙伴和开发者用最少的工作接入自己的业务，同时让业务记忆在使用中沉淀。分发的包与租户在使用中形成的资产分开管理版本：升级包不改变租户的语义、记忆和数据版本，租户资产的变化也不需要重新发布包。

| 层次 | 内容 | 主要提供方 |
| --- | --- | --- |
| 契约 | 第〇章的共享对象，以及各能力组的输入输出与失败语义 | DataAgent 团队 |
| 能力插件 | 实现一个或多个三级能力，内含不同后端或算法的适配实现 | DataAgent 团队；开放部分适配实现与方法 |
| 连接器 | 某类企业系统或文件格式的接入、结构读取和执行适配 | DataAgent 团队与伙伴 |
| 领域包 | 行业语义模板（实体、指标、规则、财务日历）、术语与同义词、领域函数声明、示例问题与评测样本、制度与数据说明、常用报表模板 | 伙伴为主，以数据和配置为主，可不写代码 |
| Preset | 组合流程、所选能力与适配实现、默认配置、验收门槛和交付形态 | DataAgent 团队与解决方案团队 |
| 租户实例 | Preset、领域包、连接器，加上使用中形成的语义、记忆和分析资产 | 运行时形成，不作为包分发 |

每个能力插件、连接器和领域包都要声明：提供哪些能力、依赖哪些能力、拥有哪类事实、适用的数据与租户范围、成本与时延上限、对应评测集、失败时的降级方式。没有评测集的能力不进入 Preset。

### 伙伴接入路径

1. 选择 Preset，安装所需连接器和行业领域包。
2. 配置数据来源或上传文件；端用户身份透传到源端，行级权限由源端执行。
3. 运行接入向导：生成语义草案和待确认清单，导入历史问答或报表数字作为评测基线（DA11.5.4）。
4. 业务确认关键定义后上线。此后的纠正和成功任务按第五章进入记忆与评测，效果由 DA11.6 跟踪。

运行、审批、审计和包分发按现有 AgentOS / MintHub 能力接入；本稿聚焦 DataAgent 的能力划分，不展开平台机制。
