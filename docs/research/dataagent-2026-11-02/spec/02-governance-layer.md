# 评测和治理层模块拆分（DA11–DA12）

> 依据：`Pluggable-DataAgent.md`（飞书 r953）。类型系统、错误模型、命名与权限约定沿用 `00-data-layer.md` §0。

## 0. 本层共性

| 项 | 约定 |
|-|-|
| 定位 | 本层不产出业务结果，产出的是**判断**与**边界** |
| 与动作面关系 | DA11.9 上线门禁、DA12.11 爆炸半径评估决定「能不能放」 |
| 判据来源 | 一律来自 DA11.5（判据与样本），不允许在评测代码里硬编码业务判据 |
| 证据 | 本层所有结论必须可回溯到样本、版本与输入 |

---

## 1. DA11 评测与验证

**模块定义**：判断「对不对、够不够好、能不能上线」。不修数据（DA02/DA12），不做业务决策（DA16）。

### 1.1 目录结构

```
packages/capabilities/dataagent-eval/
├── mint.toml
├── skills/da11-eval/SKILL.md
├── src/dataagent_eval/
│   ├── contracts.py            # Case / Judgment / GateDecision / Baseline
│   ├── tools/
│   │   ├── quality.py          # 数据质量（1.x）
│   │   ├── verify.py           # 计划与结果验证（2.x）
│   │   ├── method.py           # 方法效果（3.x）
│   │   ├── regress.py          # 回归（4.x）
│   │   ├── criteria.py         # 判据与样本（5.x）
│   │   ├── trend.py            # 持续度量（6.x）
│   │   ├── shadow.py           # 影子运行（7.x）
│   │   ├── dual.py             # 双轨评测（8.x）
│   │   └── gate.py             # 上线门禁（9.x）
│   ├── suites/{retrieval/, qa/, analysis/, rules/, engine/}
│   └── report/{diff.py, attribution.py}
└── tests/conformance/
```

### 1.2 代码结构规则

1. **判据只有一份**：评测代码从 `criteria/` 读判据，不写死在 assert 里；改判据不改代码。
2. **样本即资产**：评测集带版本与来源（人工纠正、边界反例、伙伴基线），随 bundle 发布。
3. 所有评测产出 `Judgment{结论, 置信, 失败样本[]}`，失败样本必须可定位到输入。
4. 门禁（9.x）**只读判断，不做例外**：人工豁免走 DA16 留痕，不写进门禁逻辑。

## 2. DA12 治理与资产维护

**模块定义**：让资产可管、可回滚、可追溯。不改业务口径（DA03），不做动作决策（DA15/16）。

### 2.1 目录结构

```
packages/capabilities/dataagent-governance/
├── src/dataagent_governance/
│   ├── contracts.py            # AssetVersion / ImpactSet / EvidenceChain
│   ├── tools/
│   │   ├── access.py           # 权限与脱敏（1.x）
│   │   ├── version.py          # 版本与回滚（2.x）
│   │   ├── feedback.py         # 反馈归因与建议（3.x）
│   │   ├── impact.py           # 影响分析（4.x）
│   │   ├── change.py           # 变更控制（5.x）
│   │   ├── repro.py            # 重现条件（6.x）
│   │   ├── plan.py             # 变更计划与试运行（7.x）
│   │   ├── tune.py             # 配置调优（8.x）
│   │   ├── share.py            # 跨租户沉淀（9.x）
│   │   ├── audit.py            # 证据链（10.x）
│   │   └── blast.py            # 爆炸半径（11.x）
│   └── store/{versions.py, evidence.py, policy.py}
└── tests/conformance/
```

### 2.2 代码结构规则

1. **版本是一切的主键**：数据、语义、记忆、决策缓存四类沉积物统一 `AssetVersion{kind, id, version, parent}`，回滚即切换指针。
2. 证据链（10.x）**只追加**，不改写；表达级归因（10.4）必须能落到「哪条规则、哪个子条件、哪个字段」。
3. 影响分析（4.x）输出 `ImpactSet` 供 DA11/DA16 消费，不自己下结论。
4. 权限（1.x）在**进入能力层之前**执行，任何工具不得先取数再脱敏。
