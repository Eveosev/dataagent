# 广义扩展模块拆分（DA13–DA18）

> 依据：`Pluggable-DataAgent.md`（飞书 r953）。类型系统、错误模型、命名与权限约定沿用 `00-data-layer.md` §0。

## 0. 本层构成

| 模块 | 回答什么 | 形态 | 与 DataAgent 的关系 |
|-|-|-|-|
| DA13 数据建模与物化 | 数据能不能长期好用 | 软 | 共同能力，两种形态都用 |
| DA14 持续运行与监控 | 系统能不能自己一直跑 | 软 | 共同能力，FDE 多「现场/环境」维度 |
| DA15 动作契约 | 能改什么、怎么改才安全 | 软·定 + 硬 | **FDE 支柱一** |
| DA16 委托、审批与人在环 | 谁有权批、谁来兜底 | 软·定 + 硬 | **FDE 支柱一** |
| DA17 现场上下文 | 在哪个客户、哪版能力上跑 | 硬·定 | **FDE 支柱二** |
| DA18 交付与交接 | 能不能交出去、交得掉 | 软·定 | **FDE 支柱三** |

**本层是 FDE 的增量所在**：DA13/DA14 两种形态共用，DA15–DA18 只在 FDE 形态启用。

## 1. DA13 数据建模与物化

**模块定义**：按分析需求反推目标模型并物化，让重复问题不必重复扫源。不改业务口径（DA03），不建语义关系（DA03.3）。

### 1.1 目录结构

```
packages/capabilities/dataagent-modeling/
├── src/dataagent_modeling/
│   ├── contracts.py            # ModelSpec / Contract / Materialization
│   ├── tools/{design.py, build.py, materialize.py}
│   ├── model/{star.py, contract.py}
│   └── build/{transform.py, deps.py}
└── tests/conformance/
```

### 1.2 代码结构规则

1. 模型（1.x）产出 `ModelSpec`，契约（1.2）单独成对象：字段、约束、粒度、新鲜度承诺四件齐全才算定义完。
2. 转换（2.x）只生成逻辑，不直接跑；执行走 DA07。
3. 物化（3.x）必须带校验报告，增量与回填可分别重放。

### 1.3 原子能力输入输出

| 编号 | 原子能力 | 输入 | 输出 |
|-|-|-|-|
| DA13.1.1 | 主题/维度模型设计 | 分析需求 + 画像 | `ModelSpec{事实, 维度, 粒度}` |
| DA13.1.2 | 数据契约定义 | `ModelSpec` | `Contract{字段, 约束, 粒度, 新鲜度}` |
| DA13.2.1 | 转换逻辑生成 | `ModelSpec` + 源 | 转换逻辑（可编译） |
| DA13.2.2 | 转换依赖维护 | 转换集 | DAG + 调度顺序 |
| DA13.3.1 | 增量物化 | 转换 + 水位 | 物化结果 + 新水位 |
| DA13.3.2 | 历史回填 | 转换 + 区间 | 回填结果 + 耗时/成本 |
| DA13.3.3 | 物化结果校验 | 物化结果 + 契约 | `{通过 \| 违规项}` |

## 2. DA14 持续运行与监控

**模块定义**：没有新提问时也让系统继续跑，并保持可信。不定义口径（DA03），部署归 DA17.5。

### 2.1 目录结构

```
packages/capabilities/dataagent-runtime/
├── src/dataagent_runtime/
│   ├── contracts.py            # Trigger / Signal / Budget / Fleet
│   ├── tools/{trigger.py, watch.py, alert.py, budget.py, wait.py, fleet.py, drift.py}
│   ├── watch/{freshness.py, quality.py, schema.py, metric.py}
│   └── fleet/{roles.py, handover.py}
└── tests/conformance/
```

### 2.2 代码结构规则

1. 触发（1.x）与监控（2.x/3.x）解耦：监控发现异常只发 `Signal`，不自行触发修复。
2. 告警必须**合并**（4.2），不允许一事一告警淹没值班人。
3. 等待恢复（6.x）必须幂等：续跑前先查真实状态，不假设「上次没做完」。
4. 漂移监控（8.x）对照 DA17.2 的钉定版本，不对比「最近一次」。

## 3. DA15 动作契约

**模块定义**：定义「能改什么、怎么改才安全」，并把档位与执行特性写进可发布的契约。不执行（DA07），不审批（DA16）。

### 3.1 目录结构

```
packages/capabilities/dataagent-action-contract/
├── mint.toml
├── src/dataagent_action_contract/
│   ├── contracts.py            # ActionContract / Tier / Safety
│   ├── tools/{tier.py, publish.py, safety.py, catalog.py}
│   └── store/{contracts.py, versions.py}
└── tests/conformance/
```

### 3.2 代码结构规则

1. 契约是**唯一权威**：DA07.7 网关按契约执行，代码里不得再写一套档位规则。
2. 分档（1.x）结果进契约，`A0/A1/A2` 与审批策略（1.2）必须一起发布，不允许只发档位。
3. 安全特性（3.x）四项（幂等键、dry-run、影响面预估、补偿声明）缺一，契约视为不完备，不得发布。
4. 目录（4.x）是 DA05/DA06 的动作检索入口，与契约库同源。

### 3.3 原子能力输入输出

| 编号 | 原子能力 | 输入 | 输出 |
|-|-|-|-|
| DA15.1.1 | A0/A1/A2 判定 | 动作语义 + 影响面 | `Tier` |
| DA15.1.2 | 档位与审批策略映射 | `Tier` + 权属模型 | `审批策略` |
| DA15.1.3 | 越权拒绝 | 动作 + 当前授权 | `{拒绝 + 依据}` |
| DA15.2.1 | 参数 schema | `ActionType` | JSON Schema（可校验） |
| DA15.2.2 | 前置/后置条件 | `ActionType` | 条件 AST |
| DA15.2.3 | 影响面与可逆性 | `ActionType` | `{对象集, 可逆性, 回滚}` |
| DA15.2.4 | 契约评审与版本发布 | 契约 + 评审意见 | 已发布版本 + 生效时间 |

## 4. DA16 委托、审批与人在环

**模块定义**：把决定权交到对的人手里并留下依据。不执行动作，不定义业务动作本身。

### 4.1 目录结构

```
packages/capabilities/dataagent-hitl/
├── src/dataagent_hitl/
│   ├── contracts.py            # Principal / Grant / Approval / Console
│   ├── tools/{identity.py, approve.py, console.py, segregation.py, burden.py}
│   └── store/{grants.py, approvals.py}
└── tests/conformance/
```

### 4.2 代码结构规则

1. **委托只缩不扩**：`Grant` 的有效范围 = 父授权 ∩ 本次委托，代码里做交集而非信任入参。
2. 审批必须组装证据包（2.2），无证据的审批请求不允许进入队列。
3. 监督界面（3.x）提供四件：预览、监控、复核撤销、差异裁定；裁定入口必须是「给候选方案 + 证据」而不是开放式提问。
4. 免审（2.5）与紧急豁免（4.3）一律留痕，且可被 DA12.10 追溯。

## 5. DA17 现场上下文

**模块定义**：确定「在哪个客户、哪一版能力上跑」，并把上下文裁剪到位。不定义口径正确性（DA03.10），部署见 17.5。

### 5.1 目录结构

```
packages/capabilities/dataagent-site/
├── mint.toml
├── src/dataagent_site/
│   ├── contracts.py            # Site / PinSet / ContextPack / DeployPlan
│   ├── tools/{register.py, pin.py, dispatch.py, arbitrate.py, deploy.py}
│   └── store/{sites.py, pins.py, arbitrations.py}
└── tests/conformance/
```

### 5.2 代码结构规则

1. **钉定是一组引用，不是一个版本号**：`PinSet{data, ontology, contract, policy, evalset, budget}` 六项齐全。
2. 上下文派发（3.x）传引用不复制（3.2），超出预算时给摘要并标明丢了什么。
3. 仲裁（4.x）必须记录裁决人与传播范围，并触发旧结果失效。
4. 部署（5.x）的离线包复用 DA07.10.1 的引擎获取，不另造一套。

## 6. DA18 交付与交接

**模块定义**：让客户能自己跑起来、算得清收益、退得出去。不重复造能力（复用 DA01–DA17），只做可移交形态。

### 6.1 目录结构

```
packages/capabilities/dataagent-handover/
├── src/dataagent_handover/
│   ├── contracts.py            # Runbook / Agreement / HandoverRecord
│   ├── tools/{runbook.py, console.py, knowledge.py, agreement.py, outcome.py}
│   └── templates/{runbook.md, sla.md, training.md}
└── tests/conformance/
```

### 6.2 代码结构规则

1. Runbook 从**已验证配置**生成（回放 DA11 的验证结果），不手写。
2. 交接记录必须包含：交了什么、谁接手、还差什么（未移交项要显式列出）。
3. 效果度量（5.x）必须同口径对照 DA02.15 基线，不可归因部分要标注，不外推。
