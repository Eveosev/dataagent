# Pluggable DataAgent

<callout emoji="📌">
**本版定位：只做定义。** 这一版回答「有哪些模块化能力、每个能力做什么、原子能力拆到哪一层」；不排建设顺序、不定发布形态、不做接口 schema。落地计划下一版单独出。
</callout>

# 一、范围与分层

| 层 | 是什么 | 回答的问题 |
|-|-|-|
| **DataAgent** | 以数据与语义为对象，完成理解、计算、分析与结果交付 | 问题 → 答案 |
| **General DataAgent** | 在 DataAgent 之上，建设并维护可复用的数据与语义资产 | 资产 → 可复用 |
| **FDE DataAgent** | 在客户真实环境中交付可验收结果，动作面扩展到「受控地改」 | 结果 → 可验收 |

**分水岭是动作面。** 没有 A0/A1/A2 之分，系统再强也仍是 DataAgent。本版定义的 18 个模块按需覆盖三层，不要求一次全建。

2、在 Mint GUI / Mint TUI 中，基于模块化的能力，组装成最小业务闭环

- 令才项目：使用 DataAgent Components 组装出制度提取与规则审核
- Others： COMMING SOON
</callout>

## 1.1 FDE DataAgent：三条支柱

FDE DataAgent = DataAgent + 下面三条支柱。**支柱一是分水岭**（必要条件）：没有契约下的写动作，系统仍是 DataAgent；支柱二、三决定它能否在现场交付、能否交出去。

| 支柱 | 含义 | 判据（缺一即不成立） | 承载能力组 |
|-|-|-|-|
| **一、契约下的写动作** | 动作面从「读与答」扩到「受控地改」 | 每个写动作都有档位（A0/A1/A2）、已发布契约、审批或免审证据、执行收据；所有写只走一条通道 | DA03.11–13、DA06.6–7、DA07.7–8、DA12.10–11、DA15、DA16 |
| **二、现场是一级对象** | 同一套能力在不同客户环境里跑起来，并且可复现 | 每次执行都能定位到「哪个现场 + 哪组钉定版本」；环境变化能被发现 | DA01.8–10、DA02.13–14、DA07.9、DA14.6–8、DA17 |
| **三、可验收、可移交** | 结果按客户判据验收，运行权逐环节交给客户 | 有改动前基线、影子或双轨证据、分环节门禁、移交记录、上线后效果对比 | DA02.15、DA04.7、DA11.7–9、DA11.5.5、DA12.9、DA18 |

标注约定：第三章中，整个模块属于 FDE 的在模块标题后加 **〔FDE〕**（DA15–DA18）；散落在其他模块中的 FDE 能力组在名称后加 **〔FDE〕**。共 43 个能力组，约占全部能力组的三分之一。

DA03.15 可判定性分级、DA03.16 适用范围建模、DA07.10 引擎自举与一致性验证来自规则审核场景，属于领域能力而非 FDE 特有，不加 〔FDE〕。

## 1.2 FDE 形态与 DataAgent 形态的叠加关系

不少 FDE 能力组是某个 DataAgent 能力组的「升级形态」，而不是另一件事。同一现场只启用其中一种形态，避免出现两条写通道、两套上下文。

| DataAgent 形态 | FDE 形态 | FDE 叠加了什么 |
|-|-|-|
| DA01.1 来源连接 | DA01.8 环境资源接入 + DA01.10 凭据代理与归属 | 从数据源扩到工作环境；密钥不出域 |
| DA03.10 语义冲突识别 | DA17.4 口径仲裁 | 由指定角色裁决，并传播修订 |
| DA04.5 任务上下文 | DA17.2 版本钉定 + DA17.3 上下文派发 | 跨现场、跨 Agent 的版本钉定与最小充分上下文 |
| DA06.1–5 计算计划 | DA06.6 动作计划生成 + DA06.7 契约编译 | 从「算」到「改」，含人工步骤、等待点与审批点 |
| DA07.4 变更写入 | DA07.7 动作网关 | 分档执行、幂等、dry-run、后置校验 |
| DA11.4 回归评测 | DA11.8 双轨评测 + DA11.9 上线门禁 | 加过程合规性，并按环节放权 |
| DA14.2 数据监控 | DA14.8 环境漂移监控 | 从数据扩到系统版本、权限、流程与制度 |

## 1.3 令才闭环：哪部分是 FDE

「制度提取与规则审核」本身以只读和判定为主（A0）。它天然覆盖支柱三，**是否覆盖支柱一取决于审核结论是否回写客户系统**。

| 步骤 | 能力组 | 归属 |
|-|-|-|
| 制度接入与解析 | DA01.4、DA01.5、DA02.8 | DataAgent |
| 条款可判定性与适用范围 | DA03.15、DA03.16 | 领域 |
| 规则编译 | DA03.4、DA06.3 | DataAgent |
| 单据字段抽取 | DA02.12 | DataAgent |
| 审核求值 | DA07.5、DA07.10 | DataAgent / 领域 |
| 命中归因 | DA12.10（12.10.4 表达式级归因） | FDE·支柱一 |
| 基线与验收 | DA02.15、DA11.7、DA11.5.5、DA18.5 | FDE·支柱三 |
| 差异裁定 | DA16.3（16.3.4 差异裁定入口） | FDE·支柱一 |
| **结论落地（待定）** | 回写 OA、退回单据 → DA03.11 + DA15 + DA16.2 + DA07.7；只出报告 → DA10.3 | 回写则为 FDE·支柱一；只出报告则令才只覆盖支柱三 |
| 现场与移交 | DA17、DA18.1、DA18.3 | FDE·支柱二、三 |

**待定项**：令才要作为 FDE 示范，需要明确「审核结论改客户系统里的什么、由谁审批」。否则它展示的是 DataAgent 闭环加 FDE 的验收能力，不是完整的 FDE 闭环。

# 二、定义规范

## 2.1 三级结构

| 层级 | 单位 | 定义责任 | 数量 |
|-|-|-|-|
| 一级 | **模块** | 一个可独立演进的业务域；边界由「它产出什么资产」决定 | 18 |
| 二级 | **能力组**（模块化能力） | 一个**可被装配的选择点**：有明确输入输出、可单独替换、可单独评测 | 136 |
| 三级 | **原子能力** | 一个**不可再分的动作**：只回答「做什么」，不回答「怎么做」 | 419 |

三级之间是**包含**关系，不是调用关系。模块不直接做事，它只提供能力组；能力组不直接做事，它只由原子能力组成。

## 2.2 什么算一个原子能力

五问全过才算原子能力：

| # | 判据 | 反例 |
|-|-|-|
| 1 | **单动作**：一个动词 + 一个对象 | 「读取并解析结构」→ 两个动作 |
| 2 | **实现无关**：换后端不改名 | DB / API / MCP 连接是同一原子的不同后端 |
| 3 | **可判成败**：有明确成功判据 | 「理解用户意图」→ 无法判成败 |
| 4 | **无内部分支**：需要「如果…就…」的还能拆 | 「异常时重试」→ 是流程不是能力 |
| 5 | **可单独评测**：能给一组输入与期望输出 | 「优化体验」→ 无法构造用例 |

任一条不满足，它就是**能力组**或**流程**，不是原子能力。这一条是防止能力表膨胀成愿望清单的唯一闸门。

## 2.3 能力组的定义模板

每个能力组必须回答五件事，缺一项就不算定义完成：

| 要素 | 作用 | 缺了会怎样 |
|-|-|-|
| **定义** | 产出什么 | 名字歧义，装配时靠猜 |
| **边界** | 不做什么 | 能力重叠，两处实现、两处不一致 |
| **输入 → 输出** | 能不能接上 | 装配失败，只能靠人拼 |
| **形态** | 硬 / 软；是否「定」 | 不知道谁能改，改坏无人拦 |
| **原子能力** | 拆到不可再分 | 无法评测、无法替换后端 |

## 2.4 命名规则

| 对象 | 规则 | 例 |
|-|-|-|
| 能力组 | **名词短语**，表示「能提供的东西」 | 表结构读取、动作分档 |
| 原子能力 | **动词 + 对象**，表示「做一次什么」 | 读取主键、判定档位 |
| 工具名 | `snake_case`，动词开头；**工具命名即权限** | `sql_execute`、`get_*` 自动放行 |

## 2.5 形态标记

| 标记 | 含义 | 判据 |
|-|-|-|
| **硬** | 正确性不能依赖即兴实现，Agent 只能调用不能替换 | 换一种实现就会改变结果正确性 |
| **软**（默认） | 方法、策略、参数，Agent 可改写或即时生成 | 换一种做法仍能验收 |
| **定** | 人定，Agent 可建议不可写 | 涉及权力与边界 |

三个标记正交：硬组件的参数可以是软；软组件的边界可以是定。

# 三、模块定义
### DA01｜数据接入

> **模块定义**：把外部数据源变成可引用的数据引用。不解释业务含义，不建立语义。

<callout emoji="🔌">
**接入多元化，形态统一。** 接入对象不只是数据库，还包括 OS 文件系统、SaaS、CRM / ERP / OA、消息与工单、代码仓与 CI、Web 页面等客户工作环境。它们有两个共性：

1. **接入方式统一**：都通过工具（MCP）或 API 接入，来源差异只体现在适配器上，不新增原子能力。
2. **产出形态统一**：接入后都是**类结构化数据**，即「对象 / 记录 + 字段 + 层级或关系 + 元数据」。例如文件系统是目录树加文件元数据，CRM 是客户、商机等对象及其字段，工单是带状态和字段的记录。

因此 DA02–DA05 按类结构化数据处理，不区分来源；文件内容本身（Excel、PDF、扫描件）的解析仍走 DA01.4 / DA01.5。
</callout>

| 编号 | 名称 | 形态 | 定义 | 边界 | 输入 → 输出 |
|-|-|-|-|-|-|
| DA01.1 | 来源连接 | 硬 | 接入数据库、API、MCP，管理连接与身份引用。 | 连接成功不代表来源支持执行 SQL。 | 连接配置与凭据引用 → 可用连接句柄 |
| DA01.2 | 结构读取 | 软 | 获取表列、类型、键、API 字段及源端能力。 | 不推断业务含义。 | 连接 → 表/字段/类型/键清单 |
| DA01.3 | 数据读取 | 硬 | 按字段、条件、分页或采样读取数据。 | SQL 执行统一使用 DA07.1。 | 表+字段+条件 → 行集合 |
| DA01.4 | 文件解析 | 硬 | 读取 Excel、CSV、JSON 和 PDF 文本层，保留 sheet、公式、坐标等结构。 | 不规则 Excel 入口复用 DA02 的表块检测和结构恢复；PDF 表格提取也复用 DA02，扫描件先使用 OCR。 | 文件字节 → 结构化记录 + 版面坐标 |
| DA01.5 | OCR | 硬 | 识别扫描 PDF 和图片中的文字、位置。 | 保留识别不确定性，不纠正业务数字。 | 图像或扫描页 → 文本与位置 |
| DA01.6 | 资产目录登记 | 软 | 记录资产位置、责任人、适用范围及更新承诺。复用现有目录；登记承诺与实际新鲜度分别记录。 | —。 | 资产 → 目录条目（位置/维护者/新鲜度） |
| DA01.7 | 增量与事件接入 | 软 | 持续接收变化，保留顺序、水位及补采位置。依赖来源能力；任务调度和通用重试复用平台。 | —。 | 水位或变更流 → 增量记录 |
| DA01.8 | 环境资源接入 〔FDE〕 | 软 | 把客户的工作环境（OS 文件系统、SaaS、CRM / ERP / OA、消息与工单、代码仓与 CI、Web）经工具或 API 接入为可寻址、可枚举的资源，并统一为类结构化记录。 | 来源差异只体现在适配器，不按来源新增原子；不推断业务含义；连接成功不代表可安全执行动作。 | 环境地址 → 类结构化资源记录（对象 / 字段 / 层级 / 元数据） |
| DA01.9 | 能力探测 〔FDE〕 | 软 | 获取资源能做什么、参数约束与调用限制。与 DA01.2 的区别是「能做什么」而非「有什么字段」；不把接口存在当作可安全使用。 | —。 | 资源引用 → 可执行动作与限制清单 |
| DA01.10 | 凭据代理与归属 〔FDE〕 | 硬 | 绑定凭据但不暴露给模型，登记资源归谁所有。 | 不在上下文中出现明文密钥。 | 凭据引用 → 代调用能力（密钥不出域） |

- `DA01.6.1` 资产目录登记 — 登记资产名与位置

### DA02｜数据准备与探查

> **模块定义**：把原始数据变成结构可信、可度量的表。不定义业务含义，不产出指标。

| 编号 | 名称 | 形态 | 定义 | 边界 | 输入 → 输出 |
|-|-|-|-|-|-|
| DA02.1 | 表格区域识别 | 硬 | 从页面或 sheet 中定位一个或多个表块。 | 不判断业务对象是什么。 | 页面或工作表 → 表块坐标 |
| DA02.2 | 表格结构恢复 | 硬 | 识别多行表头、合并单元格、分节、重复表头、合计行及续表结构。 | 保留原值；不能确认的拼接保留待确认状态。 | 表块 → 规整二维表（表头/类型/明细） |
| DA02.3 | 数据结构转换 | 软 | 按指定规则转置、宽长转换、展开嵌套或拼接表格。 | 不替用户决定跨表业务关系。 | 二维表 → 目标结构记录 |
| DA02.4 | 数据画像 | 软 | 统计结构、空值、基数、分布，推断字段类型、时间和记录粒度。 | 推断是候选，不直接成为业务定义。 | 表 → 字段统计与语义角色 |
| DA02.5 | Join 关系发现 | 软 | 根据键、覆盖率、基数和历史查询寻找关联候选。 | 业务关系确认归 DA03。 | 两表 → 候选键与 Join 基数 |
| DA02.6 | 数据清洗 | 软 | 按选定规则执行去重、类型转换、标准化和缺失处理。 | 保留原件和变换记录，不静默补造事实。 | 脏记录 → 清洗后记录 + 改动清单 |
| DA02.7 | 数据血缘 | 软 | 说明数据从哪里来、经过什么处理。 | 区分静态推断与实际执行记录；动态 SQL、存储过程或未覆盖的代码需标注缺口，不据此推断业务口径。 | SQL 或任务 → 表级列级依赖 |
| DA02.8 | 文档加工 | 软 | 将解析后的文档整理成保留上下文和原文位置的检索单元。 | 复用 DA01 解析，不承担检索或业务结论判断。 | 文档 → 章节/条款切分 + 原文锚点 |
| DA02.9 | 结构变化适配 | 软 | 识别字段、接口及编码变化，判断既有读取和映射是否失效。 | 修订建议不自动改变业务定义。 | 新旧结构 → 差异与映射建议 |
| DA02.10 | 修复建议与复核 | 软 | 根据质量问题提出方案，将接受、驳回和修改原因沉淀为有范围的规则。 | 执行复用 DA02.6，验证复用 DA11，不自动覆盖原数据。 | 问题清单 → 修复方案 + 验证结果 |

# 四、依赖关系

定义独立，依赖不平级。主链只有一条：

```
DA01 接入 → DA02 探查 → DA03 语义 ─┬→ DA05 召回 ─┐
                                   └→ DA06 计划 ─┴→ DA07 执行 → DA08/09/10 交付物
DA03.11 动作语义 → DA15 契约 → DA16 授权审批 → DA07.7 动作网关
DA11 评测 ←──── 全链 ◄──── DA12 治理（版本 / 证据 / 审计）
DA17 现场 ←── 钉住上述全部模块的版本
DA18 交付 ←── DA11 验收 + DA17 现场
```

三条硬约束（定义层面，不是排期）：

| 约束 | 含义 |
|-|-|
| **DA03.15 先于 DA06** | 判不了「能不能机器化」，拆解必然空转 |
| **DA11.4 先于 DA15 放权** | 没有回归就放 A1，等于无证据审批 |
| **DA17.2 先于 DA14.7** | 多 Agent 没有版本钉定，口径必漂 |
