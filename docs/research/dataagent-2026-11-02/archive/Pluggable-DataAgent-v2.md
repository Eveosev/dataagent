# 一、定位

## 1.1 DataAgent 与 FDE DataAgent

<callout emoji="💬">
DataAgent 是以数据及其语义为主要工作对象，完成理解、计算、分析和结果交付，并可沉淀、维护可复用数据资产的智能体。狭义产品**聚焦问题到答案**；广义体系则**按需覆盖数据准备、语义建设、深度分析和持续迭代运行**；FDE 方向再进一步，**从「读」扩展到「受控地改」并对业务结果负责**。
</callout>

|  | **DataAgent** | **General DataAgent** | **FDE DataAgent** |
|-|-|-|-|
| 目标 | 基于当前输入回答问题、完成分析 | 建立、维护并持续运行一段时间内的数据工作 | 在客户真实环境里交付可验收的业务结果 |
| 工作对象 | 给定数据库与语义库 | 来源数据、语义资产、分析流程 | 整个工作环境：系统、目录、SaaS、OS、人 |
| 动作范围 | A0 读 | A0 读（含数据维护写入） | A0 读 / A1 提议 / A2 执行 |
| 交付物 | 答案、SQL、图表、报告 | 数据集、语义层、流程、模型等资产 | 契约 + 动作集 + 评测集 + Runbook |
| 验收 | 答案对不对 | 资产能否复用与持续运行 | 结果正确 + 过程合规 + 可交接 |

**分水岭是动作面**，不是数据面。没有 A1/A2 之分，系统再强也仍是 DataAgent。

## 1.2 目标

<callout emoji="💬">
1、模块化能力建设，并推送到 MintHub
2、在 Mint GUI / Mint TUI 中，基于模块化的能力，组装成最小业务闭环

- 令才项目：使用 DataAgent Components 组装出令才项目的复刻

  - 制度提取
  - 规则审核
- Others： COMMING SOON
</callout>

## 1.3 复刻的定义：任务契约，不是路径复刻

「组装出令才项目的复刻」指**端到端功能**：输入制度文档与报文，产出可执行、可解释、可验收的规则库与审核判定。**不指复刻 lingcai_new 的五道门、拆解、模板等具体实现**——那些是它在自己的数据上沉积出的答案，换一组制度、一个现场，未必还是对的答案。

**路径由执行的 Agent 基于当下数据自行出方案**；人只钉四件事：

1. **任务契约**：输入 / 输出 / 验收判据 / 约束，先于运行确定（验收是「定」）
2. **轨迹必须留**：否则无法归因，也无法沉积
3. **沉积物必须过回归**：否则每次「改进」都是退化风险
4. **权限边界**：Agent 在 A0/A1 内即兴，不即兴自己的权力

令才复刻的任务契约落点（按契约要素看能力，不排路径）：

| 契约要素 | 落点 | 状态 |
|---|---|---|
| 输入：制度文档、字段库、函数库、报文样本 | DA01.4/01.5 解析、DA03.6 语义与映射 | 已有 |
| 输出：规则库、审核判定、归因报告 | DA10.3 报告、DA12.10.4 表达式级归因 | 缺归因 |
| 验收：编译率、误报/漏报、UNKNOWN 率、人工率 | DA11.5 判据与样本、DA11.4 回归 | 缺规则库回归 |
| 沉积：流程模板、字段模式、评测集 | DA04.2.4 流程模板提炼、DA12.9 领域包 | 已有 |
| 约束：60s 硬超时、A0 权限 | DA07.9 作业化、DA15.1 动作分档 | 缺作业化 |

**接口的位置**：能力级接口（每个能力的输入输出）必须有，否则无法被调用；**管线级中间产物的 schema 不预先设计**——第一次跑通时没有 schema，跑通并验收后，被证明的路径由 Agent 沉积为模板（DA04.2.4，版本归 DA12.2，回归归 DA11.4）。**接口是沉积出来的，不是设计出来的。**

## 1.4 待商榷的点（及其结论）

1、长程任务/多个子Agent的模式里；已经检索过的业务经验，指标信息等，如何在子Agent间传递；不同子Agent完成同一任务时，如何保证指标/数据口径的一致性  
→ 见 **DA17.3 上下文派发**（引用而非复制）与 **DA17.4 口径仲裁**：**口径一致靠钉住版本，不靠传递**。

2、业务 SKILL 的交付形式；DA08\~DA10 一般不会直接交付给业务，可以通过 SKILL 设定规划约束后由 Agent 实现，也可以由 Agent 即时生成。  
→ 见 2.3「硬 / 软」约定：**DA08–DA10 以软组件为主**，交付默认做法而非固定程序；硬组件只保留正确性不能依赖即兴的部分。

# 二、怎么读这张表

## 2.1 这是回顾性目录，不是建设顺序

清单里的能力大多不是设计出来的，而是在真实业务里跑出来的：令才的五道门预筛规则、批处理批大小、前置模板化，全部由真实数据实测后补充（依据记在 `gates.py` / `ql_templates.py` 的注释里）。

所以本表回答「能力可以被归到哪一格」，不回答「先建哪一个」。**建设顺序由自证能力决定**，见第四节。

## 2.2 沉 / 定：谁有权改

> **涉及「知识与参数」的是「沉」，涉及「权力与边界」的是「定」。**

| 标记 | 含义 | 要求 |
|---|---|---|
| **沉**（默认，不标注） | Agent 可基于真实运行效果补充、调优、替换实现 | 可版本化、可回归、可回滚 |
| **定**（显式标注） | 由人定义，Agent 可建议但**不得自行修改** | 不可写、只可审计；变更走人审 |

标 **定** 的位置（9 处）：DA03.12 权属模型、DA11.5.5 分层验收、DA11.9 上线门禁、DA12.11 爆炸半径与授权阈值、DA15.1 动作分档、DA16.1 身份与委托、DA16.4 权责分离、DA17.2 版本钉定、DA18.4 运营协议。

混用会出事：若 Agent 能按运行效果「优化」动作分档，它就能把 A2 自动降成 A1——那不是优化，是越权。

## 2.3 硬 / 软：以什么形态提供

> 管的是**交付形态**，与沉/定正交：沉定管「谁有权改」，硬软管「以什么形态给、Agent 能否替换实现」。

| 标记 | 含义 | 交付形态 |
|---|---|---|
| **软**（默认，不标注） | 方法、策略、参数与流程：拆解、生成、映射、预筛、分析方法 | SKILL 给默认做法；Agent 可修改、替换或即时生成 |
| **硬**（显式标注） | 正确性或安全性不能依赖即兴实现：解析、执行引擎、作业化、存储与版本、证据与审计、人工裁定入口、评测基座 | 插件，带评测集，推送 MintHub；Agent 选择与调用，**不替换内部实现** |

标 **硬** 的位置（29 处）：DA01.1、01.3、01.4、01.5、01.10、DA02.1、02.2、02.11、DA03.6、DA04.1、04.3、04.4、DA07.1–07.10、DA09.3、DA11.4、DA12.1、12.2、12.10、DA16.3、DA17.2。

两层组合的含义：**硬组件的参数仍可以是沉**（如批大小）；**软组件的边界仍可以是定**（如 DA03.15 不得放宽）。

## 2.4 包 / 非包：能不能独立发布

这是最硬的一条判据。18 个模块平铺会让人以为要发 18 个包，实际只有 **9 个可发包 + 9 个非包**。

| 可发包（9） | 形态 |
|---|---|
| DA01 数据接入 | `dataagent-connectors` |
| DA02 数据准备与探查 | `dataagent-profiler` |
| DA03 业务语义与关系 | `dataagent-ontology`（含 03.15/03.16） |
| DA05 召回检索 | `dataagent-recall` |
| DA07 计算执行 | `dataagent-executor`（含 07.9/07.10） |
| DA11 评测与验证 | `dataagent-eval` |
| DA12 治理与资产维护 | `dataagent-governance` |
| DA13 数据建模与物化 | `dataagent-materialize` |
| DA15 动作契约 | `dataagent-action-contract` |

| 非包（9） | 由谁承接 |
|---|---|
| DA04 轨迹与记忆 | AgentOS 存储与会话（`iface-store` / `iface-session`） |
| DA06 语义查询与计算计划 | Agent 行为 + SKILL + preset |
| DA08 分析 | SKILL（软组件） |
| DA09 预测、仿真与优化 | SKILL（软组件） |
| DA10 表格、可视化与交互 | SKILL（软组件） |
| DA14 持续运行与监控 | AgentOS 调度 + preset |
| DA16 委托、审批与人在环 | AgentOS `iface-policy` + 策略内容随 preset |

判据：**有输入输出、能被独立安装与评测、替换后不破坏语义**，才叫包。其余是机制、行为、资产或过程。

sql_execute 是一个可发布能力，内部可按执行场景选择适配器：

| 场景 | 执行方式 |
|-|-|
| 企业提供 SQL MCP/API | 通过支持 SQL 的工具或接口提交查询，轮询或直接取回结果。 |
| 企业允许直连数据库 | 通过数据库驱动执行，使用对应身份与方言。 |
| 端侧文件分析 | 将准备好的文件表挂载到本地 DuckDB，再执行查询。 |

执行时将可获取的查询、实际输入输出、执行状态和版本记入 DA04 轨迹，供 DA02.7 采集血缘。MCP 只返回结果而不暴露内部处理时，保留已知来源，不注明血缘

### DA15｜动作契约

把「能力」变成「可被治理地调用」的动作。**这是狭义 DataAgent 与 FDE Agent 的分水岭**：没有 A0/A1/A2 之分，系统再强也仍然只是 DataAgent。

| 二级能力组 | 三级细分能力 | 作用与边界 |
|-|-|-|
| DA15.1 动作分档 **【定】** | DA15.1.1 A0/A1/A2 判定  <br/>DA15.1.2 档位与审批策略映射  <br/>DA15.1.3 越权拒绝 | 任何能力入口先判档：A0 读、A1 提议、A2 执行。 不允许「一档通吃」的万能工具；档位不得由 Agent 依据运行效果自行调整。 |
| DA15.2 契约声明与发布 | DA15.2.1 参数 schema  <br/>DA15.2.2 前置/后置条件  <br/>DA15.2.3 影响面与可逆性  <br/>DA15.2.4 契约评审与版本发布 | 产出被人签字、可版本化的动作契约。 不跳过确认直接生效；变更须可回滚。 |
| DA15.3 安全执行特性 | DA15.3.1 幂等键  <br/>DA15.3.2 dry-run  <br/>DA15.3.3 影响面预估  <br/>DA15.3.4 补偿动作声明 | 让执行可控、可预演、可撤销。 不可逆动作必须显式标注，不能默认「可重跑」。 |
| DA15.4 能力目录 | DA15.4.1 动作检索  <br/>DA15.4.2 适用范围与限制  <br/>DA15.4.3 弃用与替代 | 让 Agent 找得到正确的动作。 不做权限判定，权限归 DA16。 |

约定：**A1 提议必须是会话内部状态**（可丢弃、不外泄）；一旦提案落到共享库、工单或消息，它就是外部副作用，须按 A2 治理。

回答两个问题：这个动作以谁的名义做、谁点了头。

| 二级能力组 | 三级细分能力 | 作用与边界 |
|-|-|-|

# 四、依赖与建设顺序

## 4.1 依赖图

模块表是清单，真实约束是边。主链只有一条：

```
DA01 接入 → DA02 探查 → DA03 语义 ─┬→ DA05 召回 ─┐
                                   └→ DA06 计划 ─┴→ DA07 执行 → DA08/09/10 交付物
                                                      │
DA03.11 动作语义 → DA15 契约 → DA16 授权审批 → DA07.7 动作网关（A1/A2 才走这条）
                                                      │
DA11 评测 ←─────── 全链 ◄─────── DA12 治理（版本 / 证据 / 审计）
DA17 现场上下文 ←── 钉住上述全部模块的版本
DA18 交付 ←────── DA11 验收 + DA17 现场
```

三条硬规则：

- **DA03.15 必须先于 DA06**：判不了「能不能机器化」，拆解就是空转。
- **DA11.4 回归必须先于 DA15 放权**：没有回归就放 A1，等于无证据审批。
- **DA17 必须早于 DA14.7 编队**：多 Agent 没有版本钉定，口径必漂。

## 4.2 建设顺序：由自证能力决定

顺序只有一条规则：**先有归因（DA12.10），再有回归（DA11.4），最后才谈放权（DA11.9 / DA15.1）。** 在此之下有两条互不阻塞的路径。

### 路径 A：A0 判定链（令才类，先跑）

| 要件 | 落点 |
|---|---|
| 任务契约 | DA11.5.1 判据先行 |
| Agent 即兴路径 | DA06.5 计算计划组合、DA08.1 问题分解 |
| 求值与作业化 | DA07.5 expression_execute、DA07.9 作业化 |
| 验收四数：编译率、误报/漏报、UNKNOWN 率、转人工率 | DA11.4 回归、DA11.7 影子 |
| 沉积为模板 | DA04.2.4 流程模板提炼、DA12.9 领域包 |

特征：纯读 + 判定（A0），**不需要 DA15–DA18 的任何一个**。第一次全即兴，验收后沉积模板；第二个现场从模板起步，只即兴增量。「其他应用快速接入」是沉积红利，不是预建连接器。

### 路径 B：FDE 受控执行链

最小闭环 `DA03.11 + DA15 + DA16 + DA07.7`，即「能提议、能审批、能执行、能核对」。

特征：跨过 A0/A2 分水岭。前提是路径 A 已积累足够的证据与回归资产，否则审批没有可依赖的证据包（DA16.2.2），免审判据（DA16.2.5）也无从触发。

### 两条路径的关系

- 共用使能件：**DA11.4 回归、DA12.2 版本、DA12.10 归因**
- A 先行：风险最低的闭环，同时为 B 生产证据
- 合起来即「从 DataAgent 到 FDE Agent」：A 验证理解与判定，B 打开受控执行

# 五、发布形态与平台约束

## 5.1 三种形态

| 形态 | 内容 | 用途 |
|---|---|---|
| **bundle** | 能力入口：`.mcp.json` + `skills/` + 资产，可带可执行文件 | 一个一级模块 ≈ 一个 bundle |
| **preset** | 精确锁版本 + 默认配置；不带代码、不注册工具；`[policy]` **只能收紧** | 一次装齐并可复现 |
| **app** | 面向最终用户的组装成品 | 交付形态 |

推论三条：

1. **契约必须是数据，不是代码**——DA15 的动作契约、DA03.14 的状态定义、DA11.5 的评测集，都要能作为资产随 bundle 分发并被版本锁定。
2. **preset 只能收紧策略**——某客户要放宽审批，只能改现场配置，不能改 preset。DA16 的策略必须分「模板（随包）」与「现场覆盖（不随包）」两层。
3. **凭据永不进包**——DA01.10 必须在运行时注入，包里只有引用。

## 5.2 三条硬约束

| 约束 | 影响 |
|---|---|
| **工具命名即权限**：`get_` / `list_` / `search_` 自动放行 | 命名即安全边界。DA15 的分档必须与命名前缀绑定，否则分档是纸面的 |
| **MCP 单请求 60s 硬超时** | 任何「跑一批」都必须 job 化，见 DA07.9 |
| **升级不迁用户数据** | DA17 的现场数据必须与包版本解耦，版本钉定自带兼容策略 |
