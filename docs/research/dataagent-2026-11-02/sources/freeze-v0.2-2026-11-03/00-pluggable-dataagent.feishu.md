# 二、定义与边界

## 2.1 三级结构

| 层级 | 单位 | 定义责任 | 数量 |
|-|-|-|-|
| 一级 | **模块** | 按稳定职责和管理对象划分的能力大类，可独立演进并与其他模块协作 | 18 |
| 二级 | **能力组**（模块化能力） | 职责相关的能力集合，提供可装配、可替换和可评测的选择点 | 141 |
| 三级 | **原子能力** | 当前建设范围内，职责明确、可独立调用或替换、可验证效果的最小复用单元；内部可以组合其他能力 | 458 |

## 2.2 形态标记

| 标记 | 含义 | 判据 |
|-|-|-|
| **硬** | 基础执行能力：按契约调用经过验证的实现，可选择或替换为验证过的等效实现 | 实现替换后仍须满足相同契约与验收要求 |
| **软**（默认） | 方法策略能力：Agent 可生成、改写方法或参数，实现与结果仍须验证 | 做法可调整，可靠性要求不因此降低 |
| **定** | 业务约束：正式目标、验收口径和权限边界由有权主体确定，Agent 可提建议 | 候选修改与正式生效分开，不得自行放宽 |

硬/软描述主要职责，定是约束标记，可与两者叠加；混合能力组可在原子能力或实现层细分。目录编号不等于发布包粒度：同一能力可有多个后端实现，多项能力也可组成 Skill / Preset / Bundle。涉及 AgentOS、MintHub 或运行平台的复用均为设计目标。

## 2.4 跨层契约

各层所引“总体跨层约定”即本节。

1. **契约包。** 共享类型提取为独立包 `dataagent-contracts`（第 0 层）。数据层、应用层、治理层、运行层只依赖它，互不导入对方实现。数据层 `src/dataagent_data/contracts/` 中的公共部分迁入该包，各层 `contracts/` 只保留本层特有类型。
2. **包内范围：**

   - 调用封套：`CallContext`、`CapabilityResult`、`Issue`、`ExecutionRef`、`Continuation`；
   - 引用：`AssetRef`、`ResourceRef`、`SnapshotRef`、`SourceAnchor`、`EvidenceRef`、`TaskContextRef`、`DeliveryRef`；
   - 统一词表：`LifecycleStatus`、`ActionTier`、`AccessDecision`、`ComponentMeta`（含 `license`）。
3. **`LifecycleStatus`：**`draft → candidate → validated → active → deprecated / invalidated / rejected`。经验用 `candidate/validated/active/deprecated`；治理资产用 `draft/validated/active/deprecated/invalidated`；程序用 `draft/validated/rejected`，是否已执行记为执行记录属性，不作为状态。
4. **依赖方向：** contracts ← data ← application；治理层、运行层只依赖 contracts，以及经端口注入的实现。
5. **类型完整度门槛：** 进入某个切片（§4.1）的原子，其输入输出类型必须在 contracts 中有字段定义；只有名字的类型不得进入切片验收。
6. **schema：** 先写类型、再生成 schema（`contracts/generated/`），不手写第二份。

类型与字段明细见 [05-contracts.md](https://modelbest.feishu.cn/docx/VavsdOWFeoLBFrxOt9JcjAsInDe)。

# 三、模块定义

DA03.15 可判定性评估、DA03.16 适用范围建模、DA07.10 引擎接入与一致性验证可用于规则审核，也可用于其他领域，不限定特定表达式或引擎实现。

### DA01｜数据接入

> **模块定义**：把外部数据源变成可引用的数据引用。不解释业务含义，不建立语义。

<callout emoji="🔌">
多源接入通过 API / MCP、数据库驱动、本地文件或其他适配器完成。后续能力按内容类型与任务需要选择，
</callout>

| 编号 | 名称 | 形态 | 定义 | 边界 | 输入 → 输出 |
|-|-|-|-|-|-|
| DA01.1 | 来源连接 | 硬 | 接入数据库、API、MCP 等来源，管理连接与身份引用。 | 负责建立可用连接；环境对象的枚举和读取由 DA01.8 复用本能力完成。连接成功不代表支持 SQL。 | 连接配置与凭据引用 → 可用连接句柄 |
| DA01.2 | 结构读取 | 软 | 获取数据库表列、类型、键，以及 API/MCP 返回对象的数据结构。 | 描述数据结构；动作参数、可执行操作和调用限制归 DA01.9，不推断业务含义。 | 连接 → 表/字段/类型/键清单 |
| DA01.3 | 数据读取 | 硬 | 按字段、条件、分页或采样读取数据。 | SQL 执行统一使用 DA07.1。 | 表+字段+条件 → 行集合 |
| DA01.4 | 文件解析 | 硬 | 读取 Excel、CSV、JSON 和 PDF 文本层，保留 sheet、公式、坐标等结构。 | 不规则 Excel 入口复用 DA02 的表块检测和结构恢复；PDF 表格提取也复用 DA02，扫描件先使用 OCR。 | 文件字节 → 结构化记录 + 版面坐标 |
| DA01.5 | OCR | 硬 | 识别扫描 PDF 和图片中的文字、位置。 | 保留识别不确定性，不纠正业务数字。 | 图像或扫描页 → 文本与位置 |
| DA01.6 | 资产目录登记 | 软 | 记录资产位置、责任人、适用范围及更新承诺。复用现有目录；登记承诺与实际新鲜度分别记录。 | —。 | 资产 → 目录条目（位置/维护者/新鲜度） |
| DA01.7 | 增量与事件接入 | 软 | 持续接收变化，保留顺序、水位及补采位置。依赖来源能力；任务调度和通用重试复用平台。 | —。 | 水位或变更流 → 增量记录 |
| DA01.8 | 环境资源接入 〔FDE〕 | 软 | 复用 DA01.1 的连接，枚举并读取文件系统、SaaS、业务系统、消息、工单、代码仓和 Web 等资源。 | 统一资源引用与元数据，保留表、文档、图像、嵌套对象和事件等内容类型，以及分页、快照、权限等来源语义。 | 业务环境 → 资源引用、内容与元数据 |
| DA01.9 | 能力探测 〔FDE〕 | 软 | 获取资源能做什么、参数约束与调用限制。与 DA01.2 的区别是「能做什么」而非「有什么字段」；不把接口存在当作可安全使用。 | —。 | 资源引用 → 可执行动作与限制清单 |

### DA02｜数据准备与探查

> **模块定义**：把原始数据变成结构可信、可度量的表。不定义业务含义，不产出指标。

| 编号 | 名称 | 形态 | 定义 | 边界 | 输入 → 输出 |
|-|-|-|-|-|-|
| DA02.1 | 表格区域识别 | 硬 | 从页面或 sheet 中定位一个或多个表块。 | 不判断业务对象是什么。 | 页面或工作表 → 表块坐标 |
| DA02.2 | 表格结构恢复 | 硬 | 识别多行表头、合并单元格、分节、重复表头、合计行及续表结构。 | 保留原值；不能确认的拼接保留待确认状态。 | 表块 → 规整二维表（表头/类型/明细） |
| DA02.3 | 数据结构转换 | 软 | 按指定规则转置、宽长转换、展开嵌套或拼接表格。 | 不替用户决定跨表业务关系。 | 二维表 → 目标结构记录 |
| DA02.4 | 数据画像 | 软 | 统计结构、空值、基数、分布，推断字段类型、时间和记录粒度。 | 推断是候选，不直接成为业务定义。 | 表 → 字段统计与语义角色 |
| DA02.5 | Join 关系发现 | 软 | 根据键、覆盖率、基数和历史查询寻找关联候选。 | 业务关系确认归 DA03。 | 两表 → 候选键与 Join 基数 |
| DA02.6 | 数据清洗 | 软 | 按选定规则执行去重、类型转换、标准化和缺失处理。 | 保留原件和变换记录，不静默补造事实。 | 脏记录 → 清洗后记录 + 改动清单 |
| DA02.7 | 数据血缘 | 软 | 说明数据从哪里来、经过什么处理。 | 区分静态推断与实际执行记录；动态 SQL、存储过程或未覆盖的代码需标注缺口，不据此推断业务口径。 | SQL 或任务 → 表级列级依赖 |

# 四、依赖关系

模块之间按任务建立依赖，不规定固定主链。任务可从表、列、值、文档、经验或已有 Skill 进入；Agent 按发现反复检索、补充语义、修正计划、生成程序和验证。已有可用资产时无需重走全部接入与建模步骤。

```text
任务 / 表列值 / 文档 / 经验
  ↔ DA05 检索数据、语义、经验与组件
  ↔ DA06 计划与重组 ↔ DA08.6 程序生成与修复
  ↔ DA07 执行 ↔ DA11 验证 → DA08/09/10 业务结果
  验证不足 → 补数 / 语义修订 / 方法替换 / 组件重选 / 再执行

DA01/02 按需提供数据与探查；DA03 维护业务语义
已认证指标经 DA06.8 委托外部语义层编译；新问题走 DA06.2/06.3，由 DA05.9 判断检索是否充分
DA04 保存轨迹与有效资产；DA12 管理授权约束、版本与审计
DA15 声明动作要求，DA16 按策略授权与审批，DA07 实施执行控制
DA17 提供业务环境配置与协作上下文
DA18 将有效方法和组件组合沉淀为 Skill / Preset / Bundle
业务验收比较端到端效果；方法与中间流程允许不同
```
