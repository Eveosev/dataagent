## 2. 四套状态机，以及「第五套」缺在哪

kernel 里已经有四套，各自有明确语义和映射（D106：`KernelTaskState ↔ RequestState`）：

| 状态机 | 位置 | 态 | 管什么 |
|---|---|---|---|
| `RequestState` | types | Accepted / Running / **NeedsHuman** / Rejected / Completed / Failed / Cancelled / **Unknown** | 一次请求 |
| `KernelTaskState` | session/handoff | Queued / Running / Completed / Failed / Cancelled / Rejected | `operation.get` 的任务视图 |
| `InterruptTaskState` | types/interrupt | Pending / Running / ResultReady / Delivering / Paused / Delivered / Cancelled / Failed | 打断任务 |
| `SessionStatus` | session/view | 会话生命周期 | 会话 |

**两个态值得单独说：**

- **`NeedsHuman`** —— kernel 已经把"人在等"作为一等状态，不是异常分支。FDE 的业务状态机不需要自己发明这个语义。
- **`Unknown`（副作用未知：禁止自动重放，只能查询/对账）** —— 这正是 FDE 最怕的场景（写了一半、回执丢了）。kernel 已经给了正确的**禁止重放**语义，这是分布式系统里最难的一课，已经替我们上过了。

**所以缺的不是状态机，是第五套：业务工作流状态机。** 它缺在两个具体的地方：

| 缺什么 | 说明 |
|---|---|
| **状态定义（可声明、可评审、可版本化）** | kernel 的四套都是**固定枚举**；业务状态是每个客户不同的 20–50 个态 |
| **长周期 timer / 定时唤醒** | `TotalTime` 预算与 `deadline_ms` 只做**超时**，不做"三天后叫醒我" |

结论修正为：

> **不是"要不要建 workflow 引擎"，而是"要不要在 OS 里加一份可声明的状态定义 + 一个 timer"。**
> 引擎的执行底座（持久化、围栏、阻塞、信号）已经有了。

## 3. A0/A1/A2 ≙ ReadOnly/Advance/SideEffect（结论不变，且更硬）

| FDE 动作档 | `EffectLevel` | 判定 |
|---|---|---|
| A0 读 | `ReadOnly` | 不改任何状态 |
| A1 提议 | `Advance` | 只改本会话状态 |
| A2 执行 | `SideEffect` | 外部副作用 |

`OP_EFFECT_MAP` 是**精确匹配 + 未登记默认 `SideEffect`**（fail-closed），`tool.exec`/`env.exec`/`model.stream` 已登记为 `SideEffect`。这套默认值直接可用。

**必须固化的规范**：提案一旦离开会话（落进共享提案库、工单、消息），它就是 `SideEffect`，必须按 A2 治理。`Advance` 的合法性来自"可丢弃、不外泄、无外部可见影响"。

## 4. 沙箱：三件已有，一件真缺

| # | 事项 | 0.1.2 现状 | 归属 |
|---|---|---|---|
| 1 | 执行隔离（fs/exec/signal 抽象） | ✅ `iface-env` | OS |
| 2 | 落位声明（本地/远端/跟随工作区） | ✅ `PlacementMode`（仅声明） | OS 声明、宿主落位 |
| 3 | 出口策略 | ✅ `EgressRequest/EgressDecision` | OS 执行、FDE 声明 |
| 4 | **供给与调度**（镜像、配额、池化、抢占、回收） | ❌ 只有 `Environment.profile: Vec<(String,String)>` 这个自由键值 | **OS 侧缺口** |

`Environment.profile` 是唯一的扩展点（如 `root`/`profile`/`os`），能塞有限信息，但装不下"cpus/mem/image/wall_clock"这类需要强校验的约束。

**修正后的建议**：沙箱供给与调度是 OS 的缺口，**不要因此把它划给 FDE**。FDE 侧只发 `JobSpec`（能力 + 上限 + 挂载 + 预算），落位由 OS 决定。

## 7. 一句话

> 0.1.2 的内核已经把「受控执行」需要的信任原语基本备齐——**缺的是业务状态定义和两个运行时零件（timer、沙箱供给）**。
> 这意味着 FDE 层的重心应该回到**模块设计**，而不是继续讨论"要不要下沉 OS"。
