## 3. 支撑度分布说明了什么

```
✅ 直接可用：1 个（FA06）
⚠️ 部分可用：7 个（FA01/03/05/07/08/11/13）
❌ 完全空白：6 个（FA02/04/09/10/12/14）
```

**两个结论：**

1. **内核的强项在"执行信任"，弱项在"业务理解与交付"。** ⚠️ 那 7 个全部是"机制有了、语义没有"——正好是 FDE 层该干的。
2. **❌ 那 6 个里，有 4 个（FA02/12/14/10）几乎是纯方法学**，不依赖内核演进。这意味着它们可以**不等 OS 就能开工**，也应该最先做原型——因为它们才是决定"是不是产品"的部分，而不是技术风险最高的部分。

## 4. 优先级：按"决定成败"而非"技术难度"排

| 优先级 | 模块 | 理由 |
|---|---|---|
| **P0** | FA04 工作流契约 · FA05 现场上下文 · FA12 现场评测 | 三个都是 ❌/⚠️ 且决定"能不能验收"。没有契约就没有判据，没有评测就无法交接 |
| **P0** | FA06 动作面（A1 档先行） | 唯一 ✅ 支撑的模块，最快能跑出东西 |
| **P1** | FA03 工作本体 · FA07 授权与人在环 · FA11 证据 | 上 A2 的前置条件 |
| **P1** | FA01 环境资源 · FA02 现场勘查 | 有真实现场时立刻需要 |
| **P2** | FA08 编排 · FA09 漂移 · FA13 成本 | 持续运行阶段才暴露 |
| **P2** | FA10 交付 · FA14 回流 | 决定规模化，但要有第一个成功现场才有意义 |

## 5. 四个还需要讨论的模块边界

这几个我没有定论，倾向如下，想听你的判断：

### 5.1 FA06 会不会造出第二套工具注册表？

`iface-tool` 的 `ToolSpec` 已经能注册动作。如果 FA06 再建一套 `ActionContract` 注册表，就会出现"工具在 A 注册、动作在 B 注册"的双写问题。

**倾向**：`ActionContract` 不做独立注册表，而是作为 `ToolSpec` 的 **sidecar**（同名同 ID，扩展字段存前置/后置/档位/补偿）。代价是契约里塞了业务语义；收益是永远只有一个真相源。

### 5.2 FA04 契约与 FA08 编排要不要合并？

契约是「定义」（人签字、可版本化），编排是「运行时」（调度、重试）。分开的理由很硬：**签字的东西不能每秒变**。

**倾向**：不合并。但两者共用同一份 `WorkflowDef`，编排只读不写。

### 5.3 FA11 证据与 FA12 评测要不要合并？

两者都吃轨迹。但**审计要严、评测要宽**——评测允许"接近正确"，审计不允许"大致合规"。合并会让审计口径被评测的容差污染。

**倾向**：不合并，共用 `TraceSink`，各自有独立的判据层。

### 5.4 FA01 是不是该降级？

`iface-env` + MCP 已经能接大部分资源。FA01 剩下的只有"业务目录与归属"，可能应该并进 FA02 现场勘查，而不是独立成模块。

**倾向**：先保留（现场要回答"这个客户有哪些系统"），但如果 P0 阶段发现它只产出清单，就并入 FA02。

## 6. 与 DataAgent 的最终关系

| DataAgent | → FDE Agent | 变化 |
|---|---|---|
| DA01 数据接入 | FA01 环境与资源 | 从"连数据源"到"连工作环境" |
| DA02 数据准备与探查 | **FA02 现场勘查**（复用算法） | 从"表结构"到"流程与角色" |
| DA03 业务语义 | FA03 工作本体 | 加动作、权属、证据 |
| DA04 轨迹与记忆 | FA05 现场上下文 + FA11 证据 | 从"任务内"到"跨周钉定" |
| DA05 召回 | 保留（跨模块能力，不单列 FDE 模块） | 检索对象扩到工具/制度/人 |
| DA06 计算计划 | FA04 工作流契约 + FA08 编排 | 从"生成 SQL"到"生成受控状态机" |
| DA07 计算执行 | **内核承接**（env/tool/effect） | FDE 只剩"分档与补偿" |
| DA08 分析 | 保留 | — |
| DA09 预测 | 保留 | — |
| DA10 交付 | FA10 交付与交接 | 从"出报告"到"能移交" |
| DA11 评测 | FA12 现场评测 | 从"答案对错"到"结果+过程" |
| DA12 治理 | FA07 授权 + FA11 证据 | 从"资产维护"到"动作治理" |
| DA13 建模物化 | 保留 | — |
| DA14 持续运行 | FA09 漂移 + FA08 编排 | 监控对象从数据扩到环境 |

**规律：DA 的 14 个模块没有一个被删除，但有一半改了名字和边界。** 这印证了 01 篇的判断——是泛化，不是替换。
