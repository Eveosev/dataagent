# incidents：告警归因

只在 `thresholds.json.escalation` 判为 P0 / P1 时建文件。P2 不建文件，记在 `monitor/trend.md` 的对应轮次与任务 `NOTES.md` 即可。

## 命名

```text
<date>-<task>-<P0|P1>-<slug>.md
2026-11-18-B01-P1-multi-row-header.md
```

## 模板

```markdown
# <标题>

- 任务：B01 不规则表格理解
- 轮次：r003-2026-11-18（基线 r001-2026-11-05）
- 指标：header_cell_accuracy 0.913 → 0.842（-7.1pp，超阻断线 5pp）
- 级别：P1

## 现象

一句话说明哪类样本坏了、坏在哪个指标，不放结论先行。

## 证据

- cases.jsonl 中失败用例：`B01-mhdr-0042`、`B01-mhdr-0051`（附 artifacts 路径）
- 变化点：模型 deepseek-v4.2；提示未变；解析器版本 0.4.1 → 0.4.2

## 归因

| 假设 | 验证方式 | 结论 |
|-|-|-|
| 新解析器丢掉第二行表头 | 对 5 条失败用例跑旧解析器 | 成立 / 不成立 |

## 处置

- 已/将要做的事，指向提交或配置项
- 是否需要回滚基线：不需要（基线未换）

## 回归验证

- 用 `x` 轮次验证修复，不进趋势
- 修复后转 `r` 轮，需在同 split 上回到门槛内

## 关闭条件

明确、可机检：例如「r004 的 unseen_acceptance 上 header_cell_accuracy ≥ 0.90 且 row_retention = 1.0」
```

## 规则

- 一条告警一个文件，不合并；同一指标连续两轮恶化要交叉引用前一个文件。
- 归因只写被证据支持的假设，未验证的放「待验证」，不得以「模型不稳定」收尾。
- 关闭后保留文件，不删：下一轮再犯时以「复发」引用。
- 因告警而放宽 `thresholds.json` 的，必须在本文件写明放宽依据与批准人。
